# 0006 競合に負けた計算の要求を持ち越す（L2-2）

> 種別：**検証（事前登録）**。このファイルと `run.py`・`analyze.py` は、測定を始める前にコミットする
> 登録日：2026-10-07
> 設計：`AnIma-ll_L2-2_計算要求の持ち越し_設計案_v0.2`（ChatGPT レビュー済み）
> 構成：脳 `minimal-v1`（順応あり）＋ 計算の要求の持ち越しだけ／偽 Kernel／時計の早送り／入力なし

## 背景

計算資源（llm_pool、容量 1）の取り合いに負けた要求は、これまで跡形もなく消えていた。L1（0002・0003）では u2 が 30 分 × 3 個体で一度も Kernel の実行権を得られず、L2-1 の順応でも変わらなかった。

L2-2 では、負けた要求を `KernelRequestOutput` の私的な状態 `pending` として残し、`pending × exp(−Δt/τ_p)` で弱まりながら毎 Pulse 再提示する。再提示は発火ではない（activity にも順応にも触らない）。計算が始まれば消え、p_min を下回れば諦める。Kernel に渡す中身は、提示する Pulse の受容野から作り直す。

この実験は「u2 を救う」ためではなく、**どの Unit も、資源の取り合いだけで長く取り残されることがなくなるか** を確かめる。1 時間の決定論的な実行なので、「永久に」取り残されないことまでは確かめられない。u2 は既知の代表例（sentinel）として記録する。

## 事前に分かっていること（測定前に確認した範囲）

- 基準（τ_p = 0、`minimal-v1`、偽 Kernel 3 秒、入力なし）の最初の 600 Pulse では、20 個体中 9 個体で u1 か u2 が一度も実行権を得られなかった（u2 だけでなく u1 も取り残される）
- 実装のテストとして、seed 2・600 Pulse・τ_p = 5 で u2 が実行権を得ることを確認した（`tests/integration/test_l0_runtime.py`）。それ以外の条件の結果は見ていない

## 条件

- τ_p ∈ {0, 2, 5, 10} 秒（0 は持ち越しなし ＝ `minimal-v1` と同じ挙動）
- p_min = 0.1 に固定（Engineering cutoff。要求の強さは 0〜1）。生存時間 ≒ τ_p × ln(強さ / p_min) なので τ_p と p_min は組で効く。ここでは τ_p だけを動かす
- 偽 Kernel の推論時間 ∈ {1, 3} 秒（1 は L1 の Ollama の 1〜2 秒に近い、3 は L0 以来の既定）
- 個体：seed 1〜20
- 入力なしで 3600 Pulse（1 時間）

## 指標

**要求の由来**：`firing`（新しい発火。持ち越しはなかった、または弱まりきって諦めた直後）／`pending`（持ち越しの再提示）／`merged`（生きている持ち越しと新しい発火の統合）。

**エピソード**：同じ Unit の要求の並び。負けた要求の次の Pulse に `pending` か `merged` の要求があれば同じエピソードが続く。「容量の取り合いに負けた」以外の結果（始まった／自分の前の計算が実行中で捨てた）で終わるか、負けたあと次の Pulse の要求がない、または `firing`（持ち越しを諦めた直後の新しい発火）なら「諦めた」で終わる。こうして、諦めた直後の新しい発火で計算が始まっても、古い要求の回収とは数えない。

**主**

- 取り残し：claim を出したのに、1 時間のうちに一度も計算が始まらなかった Unit がいる個体の数（全ての Kernel を要求する Unit について）
- 回収率：負けを含むエピソードのうち、後で計算が始まったものの割合
- 待ち時間：負けを含むエピソードの、最初の要求から計算が始まるまでの Pulse 数

**sentinel（記録）**：τ_p = 0 で取り残された Unit（u2 など）が、持ち越しありで解消するか

**コスト・ガードレール（記録）**：計算の総数、claim の総数（うち再提示）、根拠なしの計算の割合、発話の数、発火の総数（持ち越しが発火の力学を変えていないか）

## 仮説

- **H1（観測期間内の取り残しがほぼなくなる）**：τ_p ∈ {5, 10} では、1 時間のうちに一度も計算が始まらない Unit がいる個体が 20 中 1 以下になる。主張は「少なくとも 1 時間の決定論的な実行では、実行全体にわたる取り残しがほぼ解消した」までに留める
  - τ_p = 0 で取り残しのある個体が 3 以上いる推論時間の条件だけで判定する（基準で取り残しがほとんどないなら、効果を判定できないため）。どちらの推論時間でも 3 未満なら H1 は判定不能
  - H1 は、判定に使う推論時間 × τ_p ∈ {5, 10} のすべてで成り立てば支持
- **H2（負けた要求が後で計算される）**：τ_p ∈ {5, 10} では、回収率が 0.5 以上になる（τ_p = 0 では、負けた要求は持ち越されないので回収率は 0）
  - H2 は、推論時間 {1, 3} × τ_p ∈ {5, 10} のすべてで成り立てば支持
- τ_p = 2 は H1・H2 の全体の判定には使わない（用量反応として記録する）。ただし H1・H2 が正式に支持された後の参照値の選択では、事前登録した候補として条件別の基準を評価する。予備の見積もりでは、推論時間 3 秒だと要求が間に合わずに諦めることが多いと予測する

## 判定基準の読み方

seed 1〜20 は無作為に選んだ 20 個体ではない。基準は統計的な有意差ではなく、Birth State の初期条件に対する頑健性の基準である。

## 参照値の選び方（事前登録）

- **前提：H1・H2 の正式判定がともに支持された場合に限る。** どちらかが不支持（または H1 が判定不能）なら参照値は決めない
- 候補：τ_p ∈ {2, 5, 10} のうち、H1 を判定に使う推論時間すべてで、かつ H2 を両方の推論時間で、条件別に満たすもの
- その中で **最も小さい τ_p**（最も弱い持ち越し）。p_min = 0.1 に固定した条件での参照値と明記する

## 予測（参考）

- 持ち越しありでは、取り残しはほぼなくなる
- 計算の総数は増えうるが、容量 1 の資源が空いている時間に限られるので、大きくは増えない。根拠なしの計算の割合は、作り直した下書きが空になる場合に増えうる
- 発火の総数はほとんど変わらない（再提示は発火ではない）。ただし計算の結果が出力されるタイミングが変わるので、下流の Unit の発火は二次的に変わりうる

## 結果の扱い

- 支持 → 規則に従って参照値を選び、`minimal-v2`（v1 ＋ 持ち越し）を作る
- 不支持 → どの推論時間・τ_p で、取り残し・回収率のどちらが崩れたかを記録する
- 結果を見たあとの詳しい分析は「事後の探索的観察」として分けて書き、上の判定は変えない
