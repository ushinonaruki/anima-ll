# 0005 発火履歴で、発火に必要な最小の入力が上がるか

> 種別：**検証（事前登録）**。このファイルと `run.py`・`analyze.py` は、測定を始める前にコミットする
> 登録日：2026-10-06
> 前の実験：0004（H1 支持／H2 不支持）。設計は ChatGPT レビューの提案による
> 構成：0004 と同じ（脳 `minimal-v0` ＋ 順応のパラメータ、偽 Kernel、時計の早送り）。順応の仕組み（実効閾値 = threshold + adaptation）は変えない

## 背景

0004 の H2（同じ probe への反応が直前の発火履歴で変わる）は不支持だった。事後の観察では、probe（重み 0.6 と 1.0）がどちらも閾値を軽く超えていて、履歴（adaptation は conditioning ありの方が約 2 倍）が反応の違いとして出なかった。

一つの「ちょうどよさそうな弱い probe」を選び直すと、0.6 を外したのと同じ失敗を繰り返しうる。そこで今回は、**反応に必要な最小の入力の強さそのものを測る**。

## 手順

0004 のパート B と同じ。ただし conditioning と probe を別の受容器から入れ、probe の強さだけを段階的に変える。

```text
             0 ────────── 600 ── 605 ── 610 ── 615 ── 620 ─────────── 650 ─── 700
rested     ：  入力なし                                                  probe（強さ w）
adapted    ：  入力なし      conditioning（重み 1.0）× 5                  probe（強さ w）
```

- conditioning：`receptor.console` → u0（重み 1.0）から 600〜620 Pulse に 5 回（0004 の重み 1.0 の条件と同じ）
- probe：実験用に足した `receptor.probe` → u0（重み w）から 650 Pulse に 1 回。651 Pulse から u0 に見える
- w ∈ {0, 0.025, 0.05, 0.075, 0.10, 0.15, 0.20, 0.30, 0.40, 0.60}。**強さごとに独立の実行**（同じ個体・同じ枝なら 650 Pulse までは完全に同じ状態から、probe の強さだけが違う）
- 条件：0004 と同じ 10 条件（α = 0 ＋ α ∈ {0.005, 0.01, 0.02} × τ_a ∈ {30, 300, 1200}）× 20 個体（seed 1〜20）× 2 枝 × 10 強さ ＝ 4000 本
- 入力の中身は使わない

## 指標

**主：w\*（u0 をすぐに発火させる最小の強さ）**

- u0 が 651 Pulse に発火した最小の w。0.6 でも発火しなければ「0.6 より上」（不応期に当たった場合など）
- w = 0 で 651 Pulse に発火した場合（自発発火と重なった）は w\* = 0
- 個体ごとに adapted と rested の w\* を比べ、「adapted が高い／低い／同じ」に分ける

**記録（判定には使わない）**

- 651 Pulse にすぐ発火するために、あと必要だった入力の量（650 Pulse の u0 の内部状態からモデル式で計算：threshold ＋ adaptation − activity の寄与）。モデル式からほぼ直接決まる値なので、主判定にはしない
- probe の後、u0 が最初に発火するまでの潜時（w = 0.05・0.10・0.20）
- 650 Pulse の u0 の adaptation
- 強さを上げても発火しなくなる逆転（単調でない）の件数（起きないはずの確認）

## 仮説

**H2'（履歴依存）**：発火の履歴を積んだ adapted の方が、同じ個体の rested より、すぐに発火するのに必要な最小の入力（w\*）が高い。

- conditioning そのものが activity・不応期・発火の位相を変えるので、順応がなくても w\* は偶然に違いうる。そのため α = 0 を対照にする
- 条件ごとの判定：「adapted の w\* が高い個体の割合」が α = 0 より 0.3 以上高ければ、その条件で「履歴依存」
- **H2' は、α ∈ {0.01, 0.02} × τ_a ∈ {300, 1200} の 4 条件すべてで「履歴依存」なら支持**（0004 と同じ判定条件）

## 判定基準の読み方

seed 1〜20 は無作為に選んだ 20 個体ではない。「α = 0 との差 0.3 以上」は統計的な有意差ではなく、**Birth State の初期条件に対する頑健性の基準** である。

## 参照値の選び方（事前登録）

0005 の判定のあとで、標準の α・τ_a を次の規則で選ぶ（`analyze.py --with-0004`）。

- **前提：0004 の H1 と 0005 の H2' の正式判定がともに支持された場合に限る。** どちらかが不支持なら参照値は決めない（`minimal-v0` は順応なしのまま）。機構の検証が支持される前にパラメータを選ばないため
- 候補：全 10 条件のうち、0004 の H1 を条件別に満たし（20 個体中 16 以上で落ち着く）、かつ 0005 の H2' を条件別に満たす（α = 0 との差 0.3 以上）条件
- その中で **最も弱い順応** を選ぶ。弱さは α × τ_a：1 回の発火で生じる順応 a(t) = α·exp(−t/τ_a) の時間積分 ∫a(t)dt = α·τ_a、つまり **1 回の発火が後の時間に残す順応の総量**。同じなら α が小さい方

## 予測（参考）

- 0004 では、probe の時点の adaptation が adapted で rested の約 2 倍だった。w\* もそれに応じて adapted の方が高くなると予測する
- ただし activity も内在的駆動で平衡値の近くまでたまっているので、w\* そのものは小さい値（0.1 前後以下）に集まると予測する
- τ_a = 30 では順応が probe までにほぼ戻るので、差は出にくい

## 結果の扱い

- 支持 → 順応は「自発的な発火」だけでなく「入力に対する感受性」も履歴依存に変えることになる。規則に従って参照値を選び、`minimal-v0` の次の版に入れるかを決める
- 不支持 → どの条件で「高い／低い／同じ」がどう分かれたか、記録の指標（必要な入力の量・潜時）と合わせて記録する。順応の仕組みそのものを変える場合は、新しい力学の仮説として別に事前登録する
- 結果を見たあとの詳しい分析は「事後の探索的観察」として分けて書き、上の判定は変えない

## 結果

> 測定：2026-10-06 23:57、commit `744a00d`（事前登録と測定前の修正を含む版）、Claude の作業環境（Python 3.11、偽 Kernel・早送り、4000 本・277 秒）
> データ：`results.json.gz`（このフォルダ）。`analyze.py` の完全性検査を通過。強さについて単調でない例は 0 件

**判定：H2'（発火履歴で、発火に必要な最小の入力が上がる）支持**

| 条件 | adapted の w* が高い | 低い | 同じ | α = 0 との差 | w* の中央値（rested → adapted） |
|---|---|---|---|---|---|
| α = 0（順応なし） | 0.20 | 0.45 | 0.35 | — | 0.15 → 0.075 |
| α=0.005 τ=30 | 0.35 | 0.60 | 0.05 | +0.15 | 0.125 → 0.1 |
| α=0.005 τ=300 | 0.20 | 0.45 | 0.35 | +0.00 | 0.075 → 0.025 |
| α=0.005 τ=1200 | 0.95 | 0.05 | 0.00 | +0.75 | 0.025 → 0.05 |
| α=0.01 τ=30 | 0.50 | 0.30 | 0.20 | +0.30 | 0.075 → 0.1 |
| **α=0.01 τ=300** | 0.55 | 0.25 | 0.20 | **+0.35** | 0.0375 → 0.05 |
| **α=0.01 τ=1200** | 0.90 | 0.00 | 0.10 | **+0.70** | 0.025 → 0.075 |
| α=0.02 τ=30 | 0.35 | 0.35 | 0.30 | +0.15 | 0.075 → 0.0875 |
| **α=0.02 τ=300** | 0.90 | 0.10 | 0.00 | **+0.70** | 0.025 → 0.1 |
| **α=0.02 τ=1200** | 1.00 | 0.00 | 0.00 | **+0.80** | 0.025 → 0.15 |

太字が判定に使う 4 条件。4 条件とも基準（+0.3 以上）を満たした。α=0.01 τ=300 は +0.35 で、基準ぎりぎりだった。

**参照値（事前登録した規則による）：α = 0.01、τ_a = 300 秒。** 0004 の H1・0005 の H2' がともに支持されたので規則を適用した。両方を条件別に満たすのは α=0.005 τ=1200、α=0.01 τ=300、α=0.01 τ=1200、α=0.02 τ=300、α=0.02 τ=1200 の 5 条件で、その中で α × τ_a が最小（3）のものが選ばれた。α=0.01 τ=30 は H2' を満たしたが、0004 の H1 を満たさない（落ち着いたのは 20 個体中 6）ので候補から外れた。

### 事後の探索的観察（事前登録の外。上の判定は変えない）

1. **順応がなくても、conditioning のあとの方がむしろ発火しやすかった。** α = 0 では adapted の w* が低い個体が 45%（中央値 0.15 → 0.075）。conditioning で発火の位相がずれ、probe の時点で activity が閾値に近い位置にいることが多かったためと思われる。α = 0 を対照にしたのは正しかった
2. **順応が強く長いほど、差ははっきり出る。** α × τ_a が大きい条件ほど「adapted が高い」がほぼ全個体になる（α=0.02 τ=1200 で 20/20）。w* の中央値も 0.025 → 0.15 と 6 倍になった
3. **モデル式から計算した「あと必要だった入力の量」は、実際の w* と同じ向きに動いた。** 例：α=0.02 τ=1200 で 0.012 → 0.108。w* は 0.025 刻みの段階なので、計算値を少し上に丸めた値になっている
4. **潜時（記録）は、強さ 0.10 以上ではほぼすべて 0（すぐに発火）。** 強さ 0.05 では、強い順応の条件（α=0.02、τ=300・1200）で adapted 側の中央値が出なかった（半数以上が 20 Pulse 以内に発火しなかった）。弱い入力ほど、履歴の差が「反応するかどうか」に出る

### まとめ（0004 と 0005）

```text
過去に多く発火した
  ↓
現在の adaptation が高い（0004：adapted は rested の約 2 倍）
  ↓
何もなければ、自分からはだんだん発火しなくなる（0004 H1）
同じ現在の入力でも、発火に必要な強さが上がる（0005 H2'）
```
