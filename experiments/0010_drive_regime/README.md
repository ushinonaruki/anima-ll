## この実験が決めないこと

**内在的駆動の値は選ばない。** 「どの ρ が自然か」には根拠がないので、この実験で値を最適化しない。`minimal-v2` の 0.08 は、結果にかかわらずそのまま残す（値に根拠がないことは変わらない）。

この実験が調べるのは、**これまでの知見が、ρ のどの領域（自力で発火できない／臨界付近／自力で発火できる）の上でだけ成り立つのか** だけである。結果は、知見の **適用範囲** として恣意性監査に記録する。

## ρ と条件

```text
ρ = intrinsic_drive / ((1 − decay) × threshold) = intrinsic_drive / 0.075
```

（decay 0.85・threshold 0.5 は変えない。ρ は出生時のばらつきを入れる前の、設計図の上の値）

条件の正本は、実際に操作する `intrinsic_drive` の値である（`protocol.yaml`）。ρ はそこから計算する。

| intrinsic_drive | ρ | 領域 |
|---|---|---|
| 0.0500 | 0.667 | 自力で発火できない（L0 の最初の値） |
| 0.0675 | 0.900 | 自力で発火できない（臨界の手前） |
| 0.0750 | 1.000 | 臨界（ばらつきで Unit ごとに上下に分かれる） |
| **0.0800** | **1.067** | **今の値**（臨界の直上） |
| 0.0975 | 1.300 | 自力で発火できる |
| 0.1200 | 1.600 | 自力で発火できる |
| 0.1500 | 2.000 | 自力で発火できる |

- 0.08 の条件は 0009 の K1・K2 とまったく同じ設定になる（0009 の再現の確認として、結果が完全に一致することを記録する）
- 内在的駆動以外は `minimal-v2` と同じ。順応の条件は 0004・0005 と同じ 10 条件

## 再確認する知見（事前登録）

それぞれの ρ で、**元の実験と同じ手順・同じ基準** を当てはめる（0009 と同じ方法）。

**判定の値の正本は `protocol.yaml`**（基準の条件、16 個体、0.3 など）。0004 の `analyze_silent`・0005 の `analyze` からは、生の集計（条件ごとの「落ち着いた」個体数、α = 0 との差）だけを再利用し、成り立つかどうかは `protocol.yaml` の値で決める。0004・0005 の analyzer の中の定数とは独立に判定する。`protocol.yaml` の値が 0004・0005 の定数と違っていた場合は、その違いを report に記録する（今回は同じ値を書いている）。

| 記号 | 元の知見 | 手順と基準 |
|---|---|---|
| **K1** | 入力がないと落ち着く（H1） | 0004 のパート A と同じ手順（10 条件 × seed 1〜20、入力なし 3600 Pulse）。判定は 0004 の `analyze_silent`（基準の 4 条件すべてで 20 個体中 16 以上） |

### K1 の「該当しない」（先に決めておく）

「落ち着く」は、入力なしでも自発的に発火していることが前提の知見である。自力で発火できない ρ では、入力がないと発火が起きず、落ち着く・落ち着かないを問えない。

- 0004 の個体ごとの「落ち着く」は「終盤 < 序盤」かつ「終盤 < 同じ個体の α = 0 の終盤」である。α = 0 の終盤（1801〜3600 Pulse）に一度も発火しない個体は、後者を構造的に満たせない
- そこで、ある ρ の α = 0 の条件で、**終盤（1801〜3600 Pulse）に 1 回以上発火した個体が 16 未満** なら、その ρ の K1 は **該当しない（N/A）** とする（16 個体以上が落ち着くことが、構造的に起こりえないため）
- 序盤だけで見ないのは、ρ < 1 でも初期の activity の残りで序盤に一度だけ発火することがあり、続く自発活動がない個体まで「該当する」に入ってしまうため
- 該当しない ρ では K3 も N/A

### 結果の扱い（先に決めておく）

- 各知見について、ρ ごとに「成り立つ／成り立たない／該当しない」を表にし、恣意性監査の該当する行に **適用範囲**（例：「ρ ≥ 1.0 で成り立つ」「ρ ≒ 1.07 でだけ成り立つ」）として書く
- 今の値（ρ ≒ 1.07）の近くでだけ成り立つ知見は、「値に根拠のない駆動の、臨界の直上という特定の領域の上でだけの知見」と明記し、AnIma-ll の一般的な性質とは扱わない
- K3 が ρ によって別の条件を選んでも、**参照値は変えない**。ρ ごとに選ばれた条件を記録し、参照値の適用範囲として書く
- どの結果でも、内在的駆動の値を変えない。活動を抑える・補う仕組みを足さない

## 記録するもの（判定には使わない）

ρ ごとに（K1 の手順の run で）：

- 全 Unit の発火（序盤・終盤、10 分あたり）と Unit ごとの内訳
- 入力なしで一度も発火しない個体の数（seed 9 のような個体）と、自力で閾値を越える Unit の割合（出生時のばらつきを入れたあとの Unit ごとの ρ が 1 を超える割合）
- 終盤の周期パターンと変動係数（0004 と同じ定義）
- 意図の数・完了の数、列の長さ（最大・平均・終了時）と伸び続けているか、待ち時間
- 発話の回数

これらは動作テスト用の配線（恣意性監査 §3.8）と文章をやり取りする内部表現（§3.6）の上の観察であり、AnIma-ll の認知特性とは解釈しない。

## 予測（参考）

- ρ < 1 では入力なしの発火がほとんど起きず、K1 は該当しない。K2 は probe への反応を見るので、ρ < 1 でも問える
- ρ が大きいほど、activity が 0 から閾値に届くまでの時間が短くなり（ρ = 1.3 で約 9 Pulse、ρ = 2 で約 4 Pulse）、発火が増え、順応が相対的に効きにくくなる。基準の 4 条件の一部で K1 が崩れる可能性がある
- 列は、ρ が大きいほど伸び続けやすい（Kernel の性能不足として記録する）
