## 2. 命題 T-5（入力のない Unit の内在の発火の間隔）【命題】

**前提**：C0 の力学（`SimpleActivityDynamics`。Δt ＝ 1）。λ ＝ 0.85、不応 0、α ＝ 0.01、τ_a ＝ 300。出生時に θ と c は、それぞれ 0.5・0.08 の ±10 % の範囲で独立に一様（`bootstrap._build_unit` の `vary`）。出生時の activity は [0, θ/2]。入力はない（源は入口に刺激を受けない：K1）。A ＝ c／(1 − λ) と書く。

**主張**（数は `analysis.py` の出力。seed・乱数・既存の raw を使わない）
- **(a) 発火しない Unit**：A ≤ θ なら、入力のない Unit は発火しない（activity は max(初期値, A) を超えず、初期値 ≤ θ/2 ＜ θ）。出生時の範囲で A ∈ [0.48, 0.587]、θ ∈ [0.45, 0.55] なので、その割合は閉じた形で **P(A ≤ θ) ≒ 0.230** である（格子の反復でも 0.229）
- **(b) 間隔の下限**：発火して activity が 0 に戻った後、次の発火までは、順応がなくても **9 Pulse 以上**（θ 最小・c 最大の角で A(1 − λ^n) ≥ θ となる最小の n）。順応があれば、さらに長い
- **(c) 順応が積もった後の間隔（数値の観測）**：余裕 A − θ が最も大きい θ 最小・c 最大の角で反復すると、最後の間隔は 23 と 24 を繰り返す。間隔が余裕とともに短くなるなら（見込み）、範囲の全体で順応が積もった後の間隔は **23 Pulse 以上**である。(θ, c) の格子（60 × 60 の中点）の各点で反復すると（6,000 Pulse、最後の 3 間隔）、格子の上の分位は 10 %：31、25 %：39、50 %：59、75 %：101、90 %：196 Pulse である。A が θ に近いほど長く、A → θ で限りなく長くなる
- **(d) 窓の長さ**：手がかりの Unit の 1 回の駆動 w が源の活動に残す量は、n Pulse 後に w λ^n。λ^n ≤ 0.05 となる最小の n は **19**

**証明**：(a)・(b)・(d) は力学の式からの直接の計算。∎ (c) は証明ではなく、力学の部品そのものの決定論の反復で**観測した値**である（範囲の角と、格子の点）。「余裕が大きいほど間隔が短い」ので角が最も短い、という単調性は式からの見込みで、範囲の全体についての定理としては示していない。

**読み方**
- (a) は**入力のない Unit についての条件付きの解析**である。源は、手がかりの Unit とほかの源を経た駆動（1 回あたり高々 w_max ＝ 0.01）も受ける。A が θ よりわずかに小さい Unit（0 ＜ θ − A ≤ 0.01：格子で約 6 %）は、その駆動で発火しうる
- W ＝ 19 は、(c) で観測した下限 23 より短い。そのため、入力のない Unit なら、順応が積もった後に一つの窓で二回発火することはない見込みである。ただし (c) は孤立した Unit の数値の観測で、実際の源はほかの Unit の駆動も受けるので、すべての個体についての保証ではない。窓の中の発火の有無は、源の発火の相にも大きく依る
- (a) から、二つの源がどちらも入力なしで発火しうる個体の割合は、近似で約 (1 − 0.23)² ≒ 0.59 である。これは、両方の行動が出ることを求める個体の条件に関わる。ただし、源は小さな駆動を受け、窓の中の発火は相にも依るので、**0.59 を AS2b の関門が成り立つ確率とはみなさない**。**閾値（過半）は、§1 の理由（個体の多数の主張）で決め、この値に合わせて決めていない**。ここに書くのは、関門が成り立たない場合がありうることを前もって開示するためである

## 3. 手がかりの間隔 41 の導き方

- 命題 T-4：c_(k＋1) ≥ b_k ＋ L ＋ 1 ＝ c_k ＋ o ＋ W − 1 ＋ L ＋ 1 ＝ c_k ＋ 23
- 結果の 1 回の駆動の残り：窓 k の結果の刺激は遅くとも b_k ＋ L に成立し、手がかりの Unit はそれで b_k ＋ L ＋ 1 に発火しうる。その 1 回の駆動が源に届くのは b_k ＋ L ＋ 2。次の窓の始まり a_(k＋1) までに、その 1 回の駆動の残りが 5 % 以下に減るには、a_(k＋1) − (b_k ＋ L ＋ 2) ≥ 19。a_(k＋1) ＝ c_(k＋1) ＋ 2、b_k ＝ c_k ＋ 20 を入れると、**c_(k＋1) ≥ c_k ＋ 41**
- 二つのうち厳しい方の 41 を、等間隔の予定にした（乱数の流れを足さない）
- これは 1 回の駆動の減り方からの計算で、再帰の発火や痕跡（τ ≒ 6.15）を含む前の窓の影響が、次の窓で 5 % 以下になることの保証ではない

## 4. ファイル

| ファイル | 中身 |
|---|---|
| `gate_declaration.json` | 関門の組（§1）。SHA-256 は冒頭のとおり |
| `analysis.py` | 命題 T-5 の計算（設計図の値だけを読む） |
| `gate.py` | 関門を走らせるコード。②a では走らせない。宣言だけを読み、宣言のハッシュが違えば止まり、`--execute` がなければ走らない。順序は、形の確かめ → 走らせる前の点検 → 試行の札（排他）→ 本体ごとに走らせて記録を書く → 有効性 → 報告 → 試行の結末の記録。終了の値は 0（有効に完走。陰性も 0）、2（札か結果がある）、3（無効）、4（途中で失敗） |
| `attempts/`（②b で作られる） | 試行の札と結末の記録。このコードに札を消す口はない。途中で失敗したときの再開は、部分の記録の中身を読まない独立の審査の後に限る。宣言を変えればハッシュが変わり、走らせる前にレビューを要する |

**有効性の検査**（`check_validity`。どれかが合わなければ無効で、合否を出さない）
- 対の完全性：報告の行と検査用の記録の (seed, 規則 c) が、宣言の 40 seed × {A1, A2} とちょうど一致する（重複・欠落・範囲外なし）。行と記録が同じ順で対応する
- 各本体：CT-E10 の監査が ok、窓の到達が 50、終わりの未発行の予定が 0
- 各本体：層 A の窓ごとの記録から、窓・決まった窓・引き分け・発火なし・A1 が出たか・A2 が出たかを**独立に計算し直し**、報告の行と完全に一致する。層 A の窓の番号が宣言の窓とちょうど一致し、区間が宣言と同じで、結末が A1・A2・引き分け・発火なしのどれかで、結末と記録の欄（勝った源・行動 ID・決定の Pulse・出した Pulse・出したか）が整合する
- 合否（`evaluate`）は、宣言の 40 seed ごとに、c ＝ A1 と c ＝ A2 の本体が 1 つずつそろい、どちらも本体の条件を満たす個体を数える。分母は宣言の個体数 40 に固定する

**②b の運用**
- 札が排他になるのは、同じ `attempts/` を共有する一つの作業木の中だけである。②b は、一つの作業木・一つのホストで走らせ、別の clone・別のホストで並行に独立に走らせない。札には、ホスト・作業木・commit を書き、札の原本と結果を、②b の記録の PR に入れる
- 札を作る前に点検する（`preflight`）：出力先に前の報告・記録が残っている、またはこの宣言の札・結末がもうあるなら、札を使わずに止める。既存のファイルを消したり上書きしたりして回避しない
- `run_gate` は、受け取った宣言と digest を検め直さない（契約テストの入口）。運用の入口は `main` で、固定した宣言の SHA-256 を検めてから呼ぶ

## 6. 専門知識がなくても読める説明（t-k さんへ）

- 次の段階では、「手がかり」のあとの短い時間（窓）に、二つの行動のどちらが先に出るかを数えます。その前に、そもそも窓の中で行動が十分に出るかを確かめます（前方の関門）
- この文書では、その確かめに使う値（窓の長さ、手がかりの間隔、合格の基準など）を、確かめを走らせる前に決めて固定しました。後から選び直しません

- 計算から、AI の部品のおよそ 4 つに 1 つは、外からの刺激がないと自分からは動かないことが分かっています。そのため、確かめが通らない可能性もあります。通らなければ、次の段階の計画には進みません
