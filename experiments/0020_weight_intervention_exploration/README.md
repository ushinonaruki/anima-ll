## 1. 何を見たいか

0017〜0019 は「履歴由来の重みの状態が、後の誘発した活動の読み出しを変えうる」ことを示した。Q9a の検討で、素直な「12000 の介入の符号が 24000 まで残るか」は、可塑性の規則の性質（§3）からかなりの部分が構造的に決まり、新しく分かることが少ないと分かった（BLACKBOARD）。そこで、判定の問いを決める前に、次を観察する。

1. 介入した腕で、A の沈黙が破れるか（ρ_A ＜ 1 の個体でも）。ρ_A ≥ 1 でも沈黙するか
2. 2 腕の自発発火の列は分かれるか。いつ、どの Unit で、何が直接の原因で分かれるか
3. 各腕の自発活動が、A–B／A–C の重みに働く可塑性の写像（§3 の S・B）をどう変えたか。強める・弱めるの内訳
4. 反実仮想の分解 M_I・M_C の符号はどのくらい一致するか（一致しなければ活動の寄与の向きは基準に依存する）
5. ρ_A と沈黙の関係（自然な条件では 100 個体で ρ_A ＝ 1 が完全に分けた）が、介入の下でも保たれるか

ρ_A ＝ 1 は孤立した Unit の自律活動の理論上の境界で、シナプス入力を含む全 runtime の沈黙の条件ではない。この探索で適用条件や除外の規則にすることはしない（ChatGPT の判断）。

## 3. 規則の性質（記録の量の土台）

可塑性 v1.1（`src/anima_ll/neuroarchitecture/plasticity.py`）の接続 1 本の 1 Pulse の更新は

```text
w' ＝ s·w ＋ c、 s ＝ 1 − (A／w_max)·(x·[受け手が発火] ＋ y·[送り手が発火])、 c ＝ A·x·[受け手が発火]
```

（A ＝ amplitude ＝ 0.01·w_max、x・y は痕跡で発火だけで決まり w によらない、x・y ≤ 1／(1 − e^(−1/6.15)) ≈ 6.66 なので s ∈ [0.867, 1]。強める項・弱める項の係数が 1 未満なので clip は働かない）。したがって、ある時点の状態（重み w₀・痕跡）から、与えた発火の列 s で進めた重みは

```text
R(w₀, s) ＝ S(s)·w₀ ＋ B(s)、 S ＝ Π s_k ∈ (0, 1]、 B ＝ Σ c_k Π_{j>k} s_j
```

- **原点の約束**：B は **物理的な weight ＝ 0 を原点** とした切片（R(0, s)）。座標の原点を動かすと B の値は変わるので、この定義に固定する（ChatGPT の指摘）
- **実数と浮動小数点**：S ∈ (0, 1] は実数の性質。12000 Pulse の積を浮動小数点で計算すると、丸め・アンダーフローで数学的な非ゼロが実装上の 0 になりうる。そこで S と並べて log S（s ＜ 1 の Pulse の log s の和）を記録し、「S ＝ 0.0 なのに log S が有限」を監査の項目にする
- **沈黙による凍結は「厳密な不変」ではない**：A が発火しなくなっても、残った痕跡が e^(−t/6.15) で減るあいだは A→B・A→C は少しずつ更新される。更新が実効的に止まるのは痕跡が減った後（ChatGPT の指摘）
- 同じ発火の列なら、1 本ずつの差 Δw_T ＝ S·Δw₀ は符号が保たれ、0 にならず、大きさは増えない（実数として）。ΔW ＝ Δx − Δy はこの限りでない（相殺・反転しうる）

**反実仮想の分解（記録に回す。実際の runtime の媒介経路を分離したとは言わない）**：1 本ずつ ΔS ＝ S(s_I) − S(s_C)、ΔB ＝ B(s_I) − B(s_C) とすると

```text
M(基準 w_b) ＝ R(w_b, s_I) − R(w_b, s_C) ＝ ΔS·w_b ＋ ΔB
M_I ＝ M(w_I)、 M_C ＝ M(w_C)、 J ＝ M_I − M_C ＝ ΔS·(w_I − w_C)
```

M は基準について 1 次式なので、M_I・M_C は w_C〜w_I の線分の両端の値。同符号なら線分上のどの基準でも同じ向き、異符号なら向きは基準に依存し、片方だけを「活動の寄与」と呼ばない。平均化・係数は入れない。

### 7.1 一度限りの実行（guard.py。探索の seed に触れる前の保護）

探索の seed（13001〜13100）は 1 回しか走らせない。run.py は次の順で動き、どれかが満たされなければ実行しない。

1. **commit の確定（seed に触れる前）**：`--measurement-commit <40 桁>` が必須。HEAD がそれと同じで、作業ツリーがその commit と一致する（`git status --porcelain --untracked-files=all` が空。data/・__pycache__ は git の外）ことを確かめる。環境変数・"unknown" で commit を代えることはしない
2. **排他的な開始の記録**：出力先（探索では data/experiments/0020 に固定、`--out` は使えない）に `run_started.json` を O_CREAT | O_EXCL で作る（commit・seed の列・protocol.yaml の sha256・Python と OS）。開始の記録・終了の記録・結果・その一時ファイルのどれかが既にあれば、**完了・中断を問わず実行しない**（黙った再実行・上書きをしない）
3. **計測**：同時に動かすプロセスは protocol の `execution.max_workers` ＝ **2** まで（実行の前に固定。CPU 数に合わせて増やさない。1 個体 約 10 秒・100 個体 約 8 分の見積もりはこの 2 並列のもの）
3′. **保存の前の全件の一致**：結果の seed の列が期待の列（13001〜13100）と、件数・順序・重複なしで完全に一致することを確かめる。欠落・重複・別の seed・多すぎる・順序の違い・辞書でない結果があれば failed（結果は保存しない。下の 6 の失敗の扱い）
4. **終わりの確認**：HEAD・作業ツリーが開始時の commit のままで、protocol.yaml の sha256 が変わっていないことを確かめ直す
5. **原子的な保存**：結果（runs.json.gz）と終了の記録（run_finished.json、status ＝ completed・開始と終わりの commit・結果の sha256）を、一時ファイルに書いて fsync し os.replace で置く
6. **失敗したとき**：終了の記録に status ＝ failed・理由・触れた seed を残し、結果は保存しない。その seed の範囲は使用済みとして扱い、同じ範囲で再実行しない。失敗の事実と使った範囲を PR・BLACKBOARD に開示し、やり直すなら新しい範囲で（§0）

analyze.py は、開始・終了の記録がない・completed でない・commit や seed の列や sha256 が合わないデータを invalid にする。

**この保護の限界**：保護は出力先のフォルダ単位（data/ は git の外）で、別の作業場所での実行までは防げない。そのため、実行したこと（commit・時刻・結果の sha256）を PR・BLACKBOARD に記録する運用と併せて使う。

## 8. 言わないこと

- 探索の観察を「示した」「検証した」とは書かない
- ρ_A と沈黙の対応を、適用条件・除外の規則として使わない
- M_I・M_C は反実仮想であり、実際の runtime の媒介経路を分離したとは言わない。符号が一致しなければ、活動の寄与の向きを言わない
- 最初の分岐と重みの差が同時にあったことだけで、特定の接続を原因と断定しない。分岐の Pulse の activity・閾値・駆動の再構成が実際の発火と一致することは、**その Pulse の局所的な発火の判定の整合** であって、特定の接続が必要だったことや、実際の媒介の経路を分離したことの証明ではない
- M_I と M_C が 0 同士・片方が 0 のときは「向きが一致した」と書かない
- 「記憶」とは呼ばない
