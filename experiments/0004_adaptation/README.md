# 0004 発火履歴に依存する順応（L2-1）

> 種別：**検証（事前登録）**。このファイルと `run.py`・`analyze.py` は、測定を始める前にコミットする
> 登録日：2026-10-06
> 設計：`AnIma-ll_L2-1_順応_設計案_v0.2`（ChatGPT レビュー済み）
> 構成：脳 `minimal-v0`（動作テスト用の設計図）に順応のパラメータだけを足す／偽 Kernel（遅延 3 秒）／時計の早送り

## 背景

L1（0002・0003）では、Unit が一度リズムに入ると、同じ周期で永遠に発火し続けた。L2-1 では、発火の履歴が後の発火のしやすさを変える仕組み（発火頻度順応を粗視化したもの）を入れる。

```text
実効閾値 = threshold + adaptation
発火のたびに adaptation += α、時間とともに adaptation × exp(−Δt / τ_a)
```

この実験の目的は「変動係数を上げる」ことでも「不規則にする」ことでもない。乱数を使わない系で入力もなければ、順応があっても最後は一定のリズム（アトラクタ）に落ち着く（設計案 §4 の予備計算）。それで問題ない。確かめたいのは次の 2 つ。

- **落ち着くか**：何も起きていないと、発火がだんだん減っていくか
- **履歴依存か**：同じ入力に対する反応が、直前の発火の履歴だけで変わるか

LLM は関係しないので偽 Kernel で行う。主な指標は発話ではなく **Unit の発火** にする（発話には Projection・Scheduler・Kernel・Effector が混ざるため）。

## 条件

- 順応のパラメータ：α ∈ {0.005, 0.01, 0.02} × τ_a ∈ {30, 300, 1200} 秒 の 9 条件 ＋ α = 0（順応なし、τ_a は無関係）の計 10 条件
- 個体：seed 1〜20（20 個体）。α・τ_a に個体差（jitter）は掛けない。既存の個体差（threshold・intrinsic_drive のばらつきと、activity の初期値）はそのまま
- それ以外の力学のパラメータは `minimal-v0` のまま（decay 0.85、threshold 0.5、不応期 3、intrinsic_drive 0.08、jitter 0.1）
- 1 Pulse = 1 秒（時計の早送り。偽 Kernel も同じ時計で動くので、実時間と同じ結果になる）

## パート A：入力なし（H1）

- 操作：入力なしで 3600 Pulse（1 時間）
- 指標（主）：全 Unit（u0〜u3）の発火回数の合計。序盤（1〜600 Pulse）と終盤（1801〜3600 Pulse）で、10 分あたりに直す
- 指標（記録）：Unit ごとの発火、終盤の周期パターン（間隔の並びが k 個ごとに繰り返すか、k = 1〜4）と変動係数、adaptation の推移、発話回数、u2 が Kernel の実行権を得たか

**H1（落ち着く）**：順応ありでは、入力がないと発火が減っていく。

- 個体ごとの判定：「終盤 < 序盤」かつ「終盤 < 同じ個体の α = 0 の終盤」
- 条件ごとの判定：20 個体中 16 個体以上で成り立てば、その条件で「落ち着く」
- **H1 は、α ∈ {0.01, 0.02} × τ_a ∈ {300, 1200} の 4 条件すべてで「落ち着く」なら支持**（単一 Unit の予備計算で効くと予測した条件。ほかの 5 条件は用量反応として記録する）

## パート B：同じ個体から分岐させた 2 条件に、同じ probe（H2）

同じ seed・同じパラメータで、次の 2 本を回す。違いは conditioning の有無だけ。

```text
             0 ────────── 600 ── 605 ── 610 ── 615 ── 620 ─────────── 650 ─── 700
rested     ：  入力なし                                                  probe
adapted    ：  入力なし      入力    入力    入力    入力    入力           probe
```

- conditioning：600〜620 Pulse に 5 回（間隔 5 Pulse。不応期 3 より長い）。u0 を経由して u1・u2 も発火させ、順応を積ませる
- probe：650 Pulse（最後の conditioning から 30 Pulse 後）。651 Pulse から u0 に見える
- probe の強さ（receptor → u0 の結合の重み）：0.6（閾値付近）と 1.0（強い）。conditioning も同じ重みで入る
- 入力の中身は使わない（偽 Kernel も Unit も読まない）

指標：

- 反応したか：u0 が 651〜653 Pulse に発火したか
- 反応の大きさ：651〜670 Pulse の u0・u1・u2 の発火回数の合計
- 個体ごとに adapted と rested を比べ、「弱く反応」（反応しなかった、または反応は同じで回数が少ない）／「強く反応」／「同じ」に分ける

**H2（履歴依存）**：順応ありでは、直前に発火を重ねた側（adapted）が同じ probe に弱く反応する。

- 順応がなくても、conditioning で発火の位相がずれるので、adapted と rested の反応は偶然に違いうる。そのため α = 0 を対照にする
- 条件ごとの判定：「弱く反応した個体の割合」が α = 0 より 0.3 以上高ければ、その条件で「履歴依存」
- **H2 は、probe の重み 0.6 で、α ∈ {0.01, 0.02} × τ_a ∈ {300, 1200} の 4 条件すべてで「履歴依存」なら支持**
- probe の重み 1.0 は記録のみ。強い入力は順応した閾値も超えてしまうので、差は小さいと予測する

## 判定基準の読み方

seed 1〜20 は、母集団から無作為に選んだ 20 個体ではない。「16/20」「α = 0 との差 0.3 以上」は統計的な有意差ではなく、**Birth State の初期条件に対する頑健性の基準** である。

## 予測（参考）

- H1：単一 Unit の予備計算では、α = 0.01・τ_a = 300 で間隔が 18 → 79 Pulse に伸びた。ネットワークでも同じ向きに働くと予測する
- H2：probe 0.6 では、順応した u0 の実効閾値が上がっているので、反応しない・遅れる個体が増えると予測する。ただし rested 側も warm-up の 600 Pulse で自発発火による順応を積んでいるので、差は τ_a が短いと消えやすい
- 順応は claim の式を変えないので、u2 が Kernel の実行権を得られない問題（0002・0003）は残ると予測する（L2-2 の対象）。ただし発火のタイミングが変わるので、二次的に変わる可能性はある。記録する

## 結果の扱い

- 支持 → 順応を L2 の標準の力学に入れる。参照値（標準の α・τ_a）はこの結果を見てから別途決める（自然そうな挙動に合わせたチューニングにしない）
- 不支持 → どの条件で、どちらの判定（序盤との比較／順応なしとの比較、反応の有無／回数）が崩れたかを分けて記録する。H2 が不支持なら、probe の強さ・待ち時間・conditioning の回数のどれが効いていないかを、別の実験として事前登録してから調べる
- 結果を見たあとの詳しい分析は「事後の探索的観察」として分けて書き、上の判定は変えない

## 結果

> 測定：2026-10-06 23:24、commit `a368827`（事前登録を含む版）、Claude の作業環境（Python 3.11、偽 Kernel・早送り、136 秒）

**判定：H1（落ち着く）支持／H2（履歴依存）不支持**

### 事後の探索的観察（事前登録の外。上の判定は変えない）

1. **重み 0.6 と 1.0 の結果は、全 400 組で一字一句同じだった。** 重みの指定は効いている（設定を読み込むと 0.6 になっていることを確認）。この力学では、閾値を超えたかどうかだけが発火を決め、どれだけ超えたかは発火の後に影響しない（発火すると activity は 0 に戻る）。u0 の出力が u1・u2 に届く重みも probe の重みとは無関係なので、0.6 でも 1.0 でも、u0 が発火すれば下流は同じになる
2. **重み 0.6 は「閾値付近の刺激」になっていなかった。** u0 は probe に 400 本中 390 本以上で反応した（反応しなかったのは不応期に当たった回だけ）。順応した Unit は発火しにくくなる一方で、内在的駆動で activity が平衡値（≒ 0.53）近くまでたまっている。そこに 0.6 が加わると、上がった閾値（0.5 ＋ 順応 0.1〜0.2）を軽く超える。事前の「閾値付近」という見積もりは、activity が 0 付近にあると暗に仮定していた
3. **それでも、過去は状態として残っていた。** probe の時点の u0 の adaptation は、conditioning あり（adapted）が conditioning なし（rested）のおよそ 1.7〜2.6 倍だった（例：α=0.02 τ=1200 で平均 0.154 と 0.060）。履歴は「身体の状態」としては保持されているが、今回の probe と反応の測り方（u0 が発火したか・発火回数）では反応の違いとして読み出せなかった
4. **順応は「自発的な発火」を抑えるが、「入力で引き起こされる発火」はほとんど抑えない。** 現在のモデルでは、順応は activity が自力で閾値に届くまでの時間を延ばすだけで、外からの入力がそれなりに強ければ関係なく発火する
5. u2 が Kernel の実行権を得た個体は、どの条件でも 20 個体中 14 個体で変わらなかった（偽 Kernel では L1 と違い、u2 も実行権を得る個体がある）

### 次へ

- **H1 の結果から、順応を L2 の標準の力学に入れる。** 参照値（標準の α・τ_a）は、τ_a が 300 以上で効くことが分かったので、別途決める
- **H2 は、事前登録どおり別の実験として調べ直す。** 候補（いずれも事前登録してから）：
  - probe をもっと弱くする（実際に閾値付近になる強さ。例えば 0.05〜0.2）
  - 反応を「発火したか」ではなく「発火までの潜時」や「その後の発火の間隔」で測る
  - 順応を閾値ではなく activity から差し引く方式と比べる（入力で引き起こされる発火にも効くかどうか）
