## 1. なぜ 3 つを一緒に監査するか

規則・安定化・人工世界は、互いの前提になっている。

- 規則の時間の窓（痕跡の時定数）は、人工世界の刺激の間隔と比べて初めて意味を持つ
- 安定化が要るかどうか、どれくらい要るかは、規則が重みをどちら向きに動かすかで決まる
- 人工世界の結果が「経験によるもの」と言えるかは、規則と安定化が、経験と関係のない活動（内在的駆動による自発的な発火）にどう反応するかで決まる

一つずつ決めると、後から決めたものに合わせて前に決めたものを直す（症状に合わせた調整）ことになりやすい。そこで、3 つの候補と、互いの関係を先に並べる。

## 2. P1・P2 を一つの規則として書く

### 2.1 共通の形：発火の時刻の差に対する窓（カーネル）

境界の仕様 §6.3 のとおり、差 d ＝（受け手 T の発火の Pulse）−（送り手 S の発火の Pulse）とすると、

```text
d = 0     … 同じ Pulse の発火。この接続を通った因果ではないが、相関として学べる（P1）
d ≥ 1     … S が先。この接続を通った因果の候補（P2）
d ≤ −1    … T が先。この接続を通った因果ではない
```

S と T の発火の組ごとに、差 d に応じた変化 K(d) を足す、と書けば、P1 と P2 は **一つの窓 K の、d = 0 の点と d ≥ 1 の部分** として一つにまとまる。

```text
Δw = Σ（S と T の発火の組）K(d)
```

決める必要があるのは、窓 K の形である。

| 決めること | 候補 | 何を持ち込むか |
|---|---|---|
| d ≥ 1 の側 | 指数で減る（時定数 τ₊） | 新しい値 τ₊（秒）と振幅 A₊（w／θ の比） |
| d = 0 の点 | (a) d ≥ 1 側をそのまま延ばした値 (b) 別の振幅 A₀ (c) 0（P1 を入れない） | (b) は値が一つ増える。(c) は P1 を捨てる |
| d ≤ −1 の側 | (a) 0（強めるだけ） (b) 指数で弱める（τ₋、A₋） | (a) は強めるだけなので安定化が必ず要る。(b) は値が二つ増えるが、弱める側が安定化の一部を担う |

### 2.2 窓を、発火の痕跡で計算する

すべての発火の組を覚えておくのではなく、**発火の痕跡（activity trace）** を接続の rule_state に持たせれば、同じ窓（指数の形）を局所的に計算できる。

```text
接続ごとの rule_state
├─ x：S の発火の痕跡（S が発火すると上がり、τ₊ で減る）
└─ y：T の発火の痕跡（T が発火すると上がり、τ₋ で減る。d ≤ −1 側を使う場合だけ）

Pulse の境界で、この Pulse の ActivityEvent を使って
  T が発火した   → Δw に A₊ × x（前の Pulse までの S の痕跡）を足す       … d ≥ 1
  S と T が両方発火 → Δw に A₀ を足す（§2.1 の d = 0 の選び方による）    … d = 0
  S が発火した   → Δw から A₋ × y（前の Pulse までの T の痕跡）を引く     … d ≤ −1（使う場合）
  そのあと、痕跡を減らし、この Pulse の発火で痕跡を上げる
```

- **同じ Pulse の発火の扱いを、順番ではなく明示した項（A₀）で決める**。境界でまとめて計算するので、Unit を処理する順番に依存しない（境界の仕様 T4）
- 痕跡を更新する順番（先に差を使ってから、この Pulse の発火で上げる）を固定することで、d = 0 が d ≥ 1 の項に紛れ込まない
- 痕跡は接続の状態として保存される（境界の仕様 §3.1 の rule_state）

### 2.3 ほかの形の規則（今は対象外とする理由）

| 規則 | 何をモデル化するか | 今の契約との関係 |
|---|---|---|
| 発火の頻度による規則（BCM など） | 活動の高さで強める・弱めるが切り替わる。切り替えの基準が履歴でゆっくり動き、安定化を内に含む | 発火の頻度の痕跡を rule_state に持てば、ActivityEvent からでも近いものは作れる。元の形は受け手の連続した activity を使う |
| 重みの大きさを正規化する規則（Oja など） | 共起で強めつつ、重みの大きさを一定に保つ | 連続した活動を使う形が元。発火の出来事から派生した量で近似はできる |
| 三つ組の履歴（triplet）・重みに依存する更新 など | 時刻の差だけでなく、直前の発火の履歴や今の重みで変化の量が変わる | ActivityEvent ＋ rule_state で書ける |

今の契約（ActivityEvent ＋ ConnectionState）でも、時刻の差の窓以外の規則は作れる。**時刻の差の窓を選ぶのは、それしか書けないからではなく、P1・P2 という今の問いに、追加の状態をほとんど増やさずに最も直接に答える最小の候補だから** である。

BCM・Oja などを今やらない理由も「不可能だから」ではなく、**発火の頻度や連続した活動のような、新しい派生の状態を入れる独立した理由がまだないから** である（症状を見てから入れない）。

### 2.4 4 つの問い

| 問い | 時刻の差の窓（§2.1・2.2） |
|---|---|
| 症状を直すためだけか | いいえ。可塑性の監査で、症状を見る前に P1・P2 として選んだ |
| 独立した原理として説明できるか | はい。「同時・前後に活動したもののつながりが変わる」 |
| 計算資源の数を変えても同じ意味か | はい。読むのは発火の Pulse だけ。Worker・Kernel の速さは発火の時刻を通じて間接的にしか影響しない（計算資源境界 仕様 §4 と同じ扱い） |
| 副作用を次の状態で補償していないか | 強めるだけ（d ≤ −1 側が 0）なら、暴走を安定化で補償する形になる。**安定化は、暴走を見てから足すのではなく、規則と一緒に、独立した理由で先に決める**（§3） |

## 3. 安定化

### 3.1 なぜ要るか（症状からではなく）

共起で強めるだけの規則では、強まった接続がさらに共起を増やし、さらに強まる（正のフィードバック）。これは実験で見る前に、規則の形から分かる。したがって安定化は「暴走が観測されたから足す」のではなく、**規則の形から必要になるものとして、規則と同時に事前登録する**。

### 3.2 候補

| 候補 | 何をモデル化するか | 局所性 | 新しい値 | 気をつけること |
|---|---|---|---|---|
| **S1 硬い上限・下限** | 一つの接続が持てる強さには物理的な限りがある | その接続だけ | w_max（w／θ の比） | 上限に張り付くと、それ以上の経験が残らない。上限の値で結果が決まりやすい |
| **S2 柔らかい上限** | 強いほど強まりにくく、弱いほど弱まりにくい（変化の量に (w_max − w) や w を掛ける） | その接続だけ | w_max | S1 より張り付きにくい。上限の値はやはり要る |
| **S3 ゆっくり戻る** | 使われないつながりは、時間とともに初期の強さに戻る（忘却） | その接続だけ | 戻る時定数（秒） | 戻る先を初期の重み（設計図の値）にすると、設計図が「基準」の意味を持つ。戻る先の選び方も監査の対象 |
| **S4 受け手ごとの合計を保つ** | 一つの Unit が受け取れる入力の総量には限りがある（シナプスのスケーリングに近い） | 受け手 T に入る接続をまとめて見る | 合計の目標値 | 境界の仕様 §8 の 4：T に入る接続の重みの合計を読むことを許すか、ここで決める必要がある |
| **S5 弱める側の窓** | §2.1 の d ≤ −1 側。T が先に発火したとき弱める | その接続だけ | τ₋、A₋ | 強める側と弱める側の大きさの比で、全体が強まる向きか弱まる向きかが決まる。単独では暴走を止めきれないことがある |

### 3.3 重みの符号

今の設計図の重みはすべて正（興奮性）である。可塑性で重みが 0 を越えて負になると、**同じ接続が興奮性から抑制性に変わる**。これは「接続の強さが変わる」とは別の、接続の種類の変化である。最初は **重みは 0 より下にならない（下限 0）** を、安定化の候補とは別の前提として置く案をとる。抑制性の接続を入れるかどうかは、別の問いとして残す。

## 4. 受け身の人工世界

### 4.1 確かめたいこと（内部表現の原則 §6 の 4）

「A の後に B が来やすい（C は来にくい）」だけの世界で、経験のあとに **A だけを与えたとき、B の側の活動が C の側より起きやすくなるか**。報酬・正解の行動・快不快・行動の選択は使わない。LLM も使わない。

### 4.2 環境の側

| 項目 | 案 | 理由・注意 |
|---|---|---|
| 刺激の種類 | Receptor を 3 つ（ID は意味のない記号。例：`receptor.x1`〜`x3`） | どれが「A」かは環境の規則だけが知る。脳の設計図には ID だけ（AI7 と同じ考え方） |
| 刺激の出方 | 環境の規則として、遷移の確率で決める（A の次は B が出やすく、C は出にくい） | 確率・間隔は事前登録の対象。値は、規則の時定数との比で決める（§4.5） |
| 刺激の中身 | 中身は使わない | 中身を読む仕組みが無いので、意味の持ち込みは起きない。外界が感覚の Unit をどう駆動するか（感覚の駆動）は、(c2) を採ると今の「Delta の数 × 重み」のままではなくなる。§4.4 の (c2) の境界の仕様で決める |

### 4.3 脳の設計図の側

| 項目 | 候補 | 何を持ち込むか |
|---|---|---|
| Receptor から Unit へ | (a) 1 つの Receptor に 1 つの Unit（手で描く） (b) seed から決まる規則で、Receptor を複数の Unit に疎につなぐ | (a) は読みやすいが、「この Unit は x1 担当」という配線による役割の付与（恣意性監査 §3.8）に近い。ただし感覚の受容器が特定の入力にだけ反応するのは、意味の付与ではなく感覚の入口の性質とも言える。(b) は役割を描かないが、結果を読むのが難しい。**どちらを選ぶか、その理由を書くこと自体を事前登録に含める** |
| 感覚を受ける Unit どうしの接続 | すべての組を、**同じ初期の重み** でつなぐ | これが保証するのは、**設計者が A → B だけを強く配線した、という初期の配線・重みによる偏りがない** ことまでである。Birth State は対称ではない：Unit ごとに閾値・内在的駆動に ±jitter のばらつきがあり、初期の activity も seed で違う（`bootstrap._build_unit`）。したがって B 側と C 側は、生まれた時点から発火しやすさが違いうる。このばらつきは消さない（個体差は Birth State の一部）。経験の効果は、§4.6 のとおり **同じ seed どうしの比較** で取り出す |
| 可塑性の対象 | Unit どうしの接続だけ。Receptor から Unit への接続は変えない | 境界の仕様 §8 の 3 のうち、**学習の問題**（Receptor 側の「送り手の活動」をどう扱うか）だけを、この実験では「変えない」で避ける。**駆動の問題**（Receptor が Unit をどう動かすか）は、これでは解決しない（§4.4） |
| 出力 | relay だけ。kernel_request の Unit は置かない | LLM と Kernel の影響（空の出力・待ち時間・失敗）を入れない |

### 4.4 先に決める必要がある問い：発火は伝わるか

今の relay は、**新しく届いた Delta があるときだけ** 何かを送る。内在的駆動だけで発火したときは何も送らない。すると、

- 可塑性は「S が発火し、そのあと T が発火した」を見て、S → T を強める
- しかし、その S の発火は T に何も送っていない

という食い違いが起きうる。言い換えると、**接続の重みを何を見て学ぶのか**（発火）と、**その重みが何の伝わり方の強さなのか**（中身の Delta の数）がずれている。

これは症状ではなく、「伝達は中身に依存する（relay）」と「可塑性は発火に依存する（ActivityEvent）」の構造の違いから、実験の前に分かることである。扱い方の候補：

| 候補 | 内容 | 判断（案） |
|---|---|---|
| (a) そのままにする | ActivityEvent は可塑性にだけ使い、受け手を駆動するのは今までどおり Delta | **本設計としては採らない**。学ぶものと、学んだ重みが効くものがずれたまま残る |
| (b) 可塑性を「伝達が成立した発火」だけに限る | 規則が Delta の有無を読む | **外す**。境界の仕様 §6.2（Delta を読まない）に反する |
| (c1) ActivityEvent を、受け手を駆動する入力として **足す** | Delta による駆動はそのまま残し、ActivityEvent × 重み を上乗せする | **採らない**。1 回の発火が、Delta と ActivityEvent の二重で数えられる |
| **(c2) 活動の伝達と、中身の運搬を分ける** | ActivityEvent × 接続の重み が、受け手の activity を駆動する（中身に依存しない、Unit どうしの活動の結合）。Delta は中身（材料）を運ぶだけで、刺激にはならない | **最有力**。「発火 → 接続の重み → 相手の activity」になり、学ぶもの（発火の時刻の関係）と、学んだ重みが効くもの（発火の伝わる強さ）が一致する |

(c2) では、`ConnectionState.weight` は「Unit どうしの活動の結合の強さ」という一つの意味になる。生物の典型的な化学シナプスでも、送り手の発火が伝達物質の放出を起こし、STDP は送り手・受け手の発火の時刻の関係と伝達の効率の変化を結びつける。ただし AnIma-ll の Unit は神経細胞そのものではないので、これは設計を強制する根拠ではなく、整合しているという程度のアナロジーである。

**(c2) は、今の基本の力学（刺激 ＝ 届いた Delta の重みの合計）そのものを変える**。したがって 可塑性の実験（0012。番号は 0011 の基準の測定が先に入ったため）に混ぜない。順番は次のとおりにする：

```text
この監査（#38）
  ↓
活動の伝達と中身の運搬の境界 仕様（(c2) の契約を書く）
  ↓
(c2) を実装
  ↓
可塑性なしで、新しい基準（baseline）を測る
  ↓
その上で P1・P2 の規則 ＋ 安定化を決めて事前登録
  ↓
0012（可塑性の実験）
```

0007〜0010 の結果に合わせて (c2) を調整しない。それらは **旧 minimal の足場の上で得られた知見** として、そのまま残す。境界の仕様（`docs/connection-state-spec.md`）§8 の 1 は、この順番の中で決める。

**(c2) の境界の仕様で、明示的に決める論点：感覚の駆動（Receptor → Unit）**

Receptor は Unit ではないので、ActivityEvent を持たない。(c2) で Delta が刺激にならなくなると、外界が最初の感覚の Unit をどう動かすかが未定義になる：

```text
Environment → Receptor → ？？？ → 最初の感覚の Unit
```

これは「Receptor → Unit を可塑性の対象外にする」（§4.3）では解決しない。学習の問題ではなく、**外界が脳をどう駆動するか** という境界の問題だからである。したがって (c2) の境界の仕様では、少なくとも次の 3 つを分けて書く：

```text
Unit → Unit         … ActivityEvent × 接続の重み による活動の伝達
Receptor → Unit     … 感覚の駆動（sensory drive）を別に定義する
Delta               … 中身・材料を運ぶだけ
```

感覚の駆動の表し方（Receptor 由来の Delta だけを刺激として使う、`SensoryEvent` のような別の出来事にする、など）は、ここでは決めない。ただし、**Runtime が「これは Receptor 由来だから刺激にする」と意味で判断する構造にはしない**。どこで感覚の駆動が成立し、Runtime は何を機械的に運ぶだけなのか、その境界も同じ仕様で決める。

### 4.5 時間の尺度の比

結果は、次の値どうしの **比** で決まる。値そのものではなく比で事前登録する（台帳 §3.9）。

```text
刺激の間隔（A から B までの時間）
発火の痕跡の時定数 τ₊（τ₋）
入力を積み上げる時間の窓 τ_m ≒ 6.2 秒（decay 0.85／秒から）
内在的駆動による自発発火の周期（ρ ≒ 1.067 から決まる）
Delta の保持期間（10 Pulse）
順応の時定数 τ_a ＝ 300 秒
1 Pulse ≒ 1 秒（時間の解像度）
```

### 4.6 経験と関係のない活動との区別（対照の条件）

今の Unit は、入力がなくても内在的駆動で周期的に発火する（ρ ≒ 1.067 は臨界の直上）。そのため、**刺激と関係なく、自発発火どうしの偶然の共起・前後関係で重みが変わる**。これを経験の効果と区別しなければならない。

- **ρ を下げて自発発火を止める、といった調整はしない**（実験の結果に合わせて力学の値を変えることになる。ρ の依存は別の実験の問い）
- 代わりに、対照の条件を事前登録する：
  - **刺激なし**：同じ時間、刺激を与えない（自発活動だけによる重みの変化）
  - **順序を崩した刺激**：A・B・C の出る回数は同じで、順序だけをランダムにする（「A の後に B」という構造だけを取り除く）
- **比べるのは同じ seed（同じ Birth State）どうし**：同じ seed で「経験の前 → 経験 → 経験の後」を測り、さらに同じ seed の「刺激なし」「順序を崩した刺激」と比べる。生まれつきの B 側・C 側の差は、この比較で打ち消される
- 「経験で構造が変わった」と言えるのは、**順序のある条件だけに、経験の前より大きい A → B 側の非対称が現れたとき**

### 4.7 何を測るか

- **主な指標は活動**（内部表現の原則：意味は活動のパターンに宿る）：経験のあとに A だけを与え、決めた窓の中で、B 側と C 側の Unit がどれだけ発火するか。経験の前と比べ、対照の条件と比べる
- **重みは仕組みの確認に使う**：w(A 側 → B 側) と w(A 側 → C 側) の差。主な指標にはしない
- 複数の seed（個体）で行う。seed ごとの結果も報告する（0010 の seed 9 のように、ほとんど発火しない個体が出うる）
