### 0.3 結論の先取り

1. **I2 は、Core を変えずに作れる見込みである**（§2）。ただし、意図は**決定の翌 Pulse**に生まれる
   - 今の Pulse の順序では、同じ Pulse の発火の集まりは Unit の呼び出しの順に依らない（命題 T-1）。だから、二つの源の「その Pulse に発火したか」の組で、対称に決められる
   - 一方、Core には、全 Unit の呼び出しの後に Delta を足せる口がない。先に呼ばれた源の口は、後に呼ばれる源の発火を知らずに、自分の提案を返し終える。そのため、Core を変えずに、決定と同じ Pulse に、勝った源の出どころで意図を出すことはできない（命題 T-2）
   - 第一候補（方式 1）：二つの源を包む**競合の口**と、二つが共有する**I2 の決定の部品**で作る。決定は、両方の源の報告がそろった後に、二つの発火の有無だけの対称な関数で行う。意図は、決定の翌 Pulse に、勝った源の口から 1 つだけ出す
2. **同時は引き分け**：窓の中の最初の発火の Pulse に、二つの源が両方発火したら、その窓は意図なしで閉じる（§2.5）
3. **窓は、手がかりの外の予定から決まる Pulse の区間**である。I2 の決定の部品は、その区間の写しを組み立ての時に受け取る。Unit は窓の予定を何も受け取らない（§2.5・EC-10）
4. **世界**（§3）：結果の刺激は、規則 c が指す行動 ID の意図にだけ、手がかりの Receptor に返す。選択の発火から結果の刺激までは、最短で 2 Pulse である（命題 T-3）。手がかりと結果の予約が重ならない条件を、予定の制約として書く（命題 T-4）
5. **複製・再生・移植・介入**（§4・§5）：AS1 の契約と道具をそのまま引き継ぎ、Σ に I2 の決定の部品の状態を足す
6. **C0 への還元**（§6）：出口を外す、または世界が意図に応じないとき、C0 と同じ軌道になることを契約テストにする
7. **前方の関門**（§7）：窓の中で選択が測れる形で出るかを、解析と合成の seed の契約テストだけで確かめる。関門で使う値と規則の完全な組（o・W・手がかりの予定・L・同時の扱い・規則 c の割り当て・合否の閾値・個体数・seed など）は、②a で、関門を走らせる前に固定し、③はそれを引き継いで変えない。成り立たなければ、AS2b の事前登録に進まない
8. **記録は二層**（§2.8）：決定の部品は、確定の前に知りうる記録だけを持つ。意図の Delta の識別子は Runtime・Effector・世界の側の記録から得て、二つの対応は研究用の外部の突合で確かめる
9. ここに書いた方式は、どれも**実装で確かめたものではない**。②a の契約テストを通すまで、見込みである

## 2. 契約 1：窓の中の先着一意図（I2）

### 2.1 今のコードでの事実【既存の事実】

- `PulseRuntime.run_pulse`（`src/anima_ll/runtime/pulse_runtime.py`）の順序
  1. 感覚の出来事の収集と、その伝達（駆動は次の Pulse に届く）
  2. この Pulse の View を作るスナップショットを、一つだけ作る
  3. 終わった計算の結果を返す（AS2b では使わない）
  4. 全 Unit を進める：`for unit in self._units.all()` で、Unit ごとに同じスナップショットから View を作り、`unit.tick(view, context)` を呼ぶ。発火した Unit は `fired` に足し、その発火の伝達の駆動を作る（次の Pulse に届く）。提案された Delta を集める
  5. 計算の意図（AS2b では使わない）
  6. Delta の確定、駆動の積分（`BrainStateIntegrator.integrate`。駆動は次の Pulse にだけ届く）、可塑性の更新（`apply_activity(fired, …)`）
  7. Effector 宛ての Delta を配送する（4 で集めたもの）
- `UnitRegistry.all()` は Unit を ID の順で返す（`src/anima_ll/runtime/unit_registry.py`「呼び出し順を決定的にするため」）
- `GenericCognitiveUnit.tick` は、View の駆動の重みの和と自分の状態だけから発火を決める。発火したら `step.activity` を持つ（`src/anima_ll/unit/generic_cognitive_unit.py`）
- **4 の後に Delta を足せる口はない**。6 の `apply_activity` は、その Pulse の発火の全体を受け取るが、Effector 宛ての Delta を分けた後に呼ばれ、Delta を足せない。また、接続の状態の口は重みの責務の部品である
- 研究用の組み立ての口：`build_application` の `unit_overrides`・`effector_overrides`・`receptor_overrides`・`connection_wrapper`（`src/anima_ll/bootstrap.py`）。AS1 の道具（`experiments/as1_closed_loop/as1.py`）は、源を `IntentSourceUnit` で包み（I1。発火した Pulse に意図を 1 つ足す）、世界・Receptor・Effector・接続の口を差し替えて作った。Core は変えていない
- 既存の出力の部品は、自分の Unit の発火しか見ない（三段の比較 §2.3）

### 2.2 命題 T-1（同じ Pulse の発火の集まりは、Unit の呼び出しの順に依らない）【命題】

**前提**：§2.1 の順序。Unit の `tick` は、その Pulse のスナップショットから作った View と、自分の状態だけを読む。Pulse t の中で作られた駆動と Delta は、Pulse t ＋ 1 以後にしか届かない。

**主張**：Pulse t にどの Unit が発火するかは、Pulse t のスナップショットと、各 Unit の Pulse t − 1 の終わりの状態で決まり、Pulse t の中で Unit を呼ぶ順に依らない。

**証明**：Unit i の Pulse t の発火は、View_i(t) と状態 S_i(t − 1) の関数である。View_i(t) は Pulse t の 2 で作った一つのスナップショットから作られ、4 の中で変わらない。ほかの Unit の Pulse t の呼び出しが作る駆動・Delta は 6 で積分され、Pulse t ＋ 1 から見える。S_i(t − 1) はほかの Unit の Pulse t の呼び出しで変わらない。∎

**帰結**：二つの源の「Pulse t に発火したか」の組 (f_1(t), f_2(t)) は、呼び出しの順に依らない事実として定まる。I2 の決定を、この組の対称な関数にすれば、決定は呼び出しの順に依らない。

### 2.3 命題 T-2（Core を変えずに、決定と同じ Pulse に、勝った源の出どころで意図を出すことはできない）【命題】

**前提**：§2.1。研究用の部品が提案を足せるのは、Unit の `tick`（4）の戻り値だけで、4 の後に Delta を足す口はない。I2 の同時の扱いは対称にする（§2.5）。

**主張**：Pulse t に、二つの源のうち ID の順で先に呼ばれる方（以下「先の源」）が発火したとき、先の源の `tick` は、後に呼ばれる源が Pulse t に発火するかを知らずに戻る。したがって、先の源の口は、Pulse t に「自分が単独で先着した」ことを確かめて意図を出すことができない。Pulse t の 4 の中で、両方の発火を知って意図を出せるのは、後に呼ばれる源の口だけで、その意図の Delta の出どころ（`source_id`）は、勝った源が先の源のとき、勝った源と食い違う。∎

**帰結**：Core を変えずに作るなら、(a) 決定の翌 Pulse に勝った源の口から出す（方式 1）、(b) 同じ Pulse に後に呼ばれる源の口から出す（方式 2）、のどちらかになる。同じ Pulse に勝った源の出どころで出すには、Core に段を足す必要がある（方式 3）。

- 先の源の口が、後の源の状態と View を読んで、その発火を先回りして計算する形も考えられるが、ほかの Unit の状態を読み、力学の計算を出口の側で重ねて持つことになるので、採らない（EC-2）
- **T-2 の範囲**：T-2 は、この文書の前提（研究用の部品は Unit の `tick` の戻り値のほかに提案を足さない、ほかの Unit の発火を先回りして計算しない）のもとでの不可能性である。Core を変えないすべての方式について、数学的に不可能だとは言わない

### 2.5 方式 1 の部品と、決定の規則【候補】

**部品**
- **競合の口**（2 つ。源 1・源 2 をそれぞれ包む。AS1 の `IntentSourceUnit` と同じ `unit_overrides` の口で入れる）
  - 中の Unit の `tick` をそのまま呼び、その結果（提案と発火）を変えずに返す
  - 中の Unit の `tick` の後に、その Pulse に発火したか（`step.activity` があるか）だけを、決定の部品に報告する
  - 決定の部品が「この Pulse に、この口が意図を出す」と示したときだけ、出力路 `intent` に意図の提案を 1 つ足す
- **I2 の決定の部品**（1 つ。二つの口が共有する）
  - 持つもの：窓の区間の列 [(k, a_k, b_k)]（組み立ての時に受け取る、変わらない写し）、源と行動 ID の対応、各窓の状態、出す予定の意図（高々 1 つ）、その Pulse の報告、記録

**Pulse t の手順**（どちらの口が先に呼ばれても同じになる）
1. 口 u が呼ばれる：中の Unit の `tick` を呼ぶ
2. 出す予定の意図が「Pulse t に、口 u が出す」なら、口 u は意図の提案（中身は u の行動 ID）を 1 つ足し、決定の部品はそれを出したと記録する
3. 口 u は、Pulse t に発火したか f_u(t) を報告する
4. 二つの報告がそろったら（後に呼ばれた口の 3 の後）、決定の部品は次を行う
   - t が、まだ決まっていない窓 k の中（a_k ≤ t ≤ b_k）にあり
     - f_1(t) と f_2(t) の一方だけが真 → その源の勝ち。窓 k を閉じ、「Pulse t ＋ 1 に、勝った源の口が出す」を出す予定に置く
     - 両方が真 → 引き分け。窓 k を意図なしで閉じる
     - 両方が偽で t ＝ b_k → 発火なし。窓 k を意図なしで閉じる
   - それ以外（窓の外、閉じた窓の中）→ 何もしない
   - その Pulse の報告を空にする

**同時の扱い（引き分け）の理由**：二つの源を対称に扱い、どちらかを外の規則で選ばない（K6、AI2〜AI4）。引き分けの後も窓を開けておく案（後の単独の発火を勝ちとする）もありうるが、引き分けの後の力学に依る新しい分岐を足すので、最小の形として「閉じる」を第一候補にする【候補。②a で、関門の前に確定し、③で変えない】

## 3. 契約 2：世界の規則（AS2b）

### 3.1 命題 T-3（選択の発火から結果の刺激までは、最短で 2 Pulse）【命題】

**前提**：方式 1（意図は決定の翌 Pulse）。命題 W-1（意図の Pulse e に対して、結果は e ＋ L − 1、L ≥ 2）。

**主張**：窓の選択の発火が Pulse t なら、意図は t ＋ 1、結果の刺激は t ＋ L（≥ t ＋ 2）に成立する。手がかりの Unit がそれで発火するのは、G-3 の条件のもとで t ＋ L ＋ 1 である。∎

- AS1 の I1 と同じ L なら、源の発火から結果までが 1 Pulse 長い。命題 G-5 の上限は、源から手がかりの Unit への組について、κ^(L−1) ではなく κ^L になる。L の値は、②a で、この遅れを入れて、関門を走らせる前に、独立の理由で決める（§7.2）

### 3.2 命題 T-4（手がかりと結果の予約が重ならない条件）【命題】

**前提**：T-3。窓 k の結果は、窓の中の決定（t ≤ b_k）からだけ生まれる。

**主張**：c_(k＋1) ≥ b_k ＋ L ＋ 1 なら、窓 k の結果の刺激（Pulse ≤ b_k ＋ L）は、次の手がかり c_(k＋1) より前に成立し、手がかりの Receptor の同じ Pulse に、手がかりの予約と結果の予約が重ならない。結果の予約どうしも重ならない（勝ちの窓 1 つに意図 1 つ）。∎

- この条件を予定の制約とすれば、手がかりの Receptor の 1 Pulse の予約は高々 1 つで、多重度の規則（AS1 の WC-1c）の選び方は感覚の列を変えない（AS1 の命題 W-2 と同じ形）

## 7. 前方の関門：窓の中で選択が測れる形で出るか（基準 §7）

### 7.1 位置づけと原則

- 成り立たなければ、SC-1（選択の問い）を満たさないので、AS2b の事前登録（③）に進まない
- 確かめは、解析と、合成の seed の契約テストだけで行う。smoke の結果を見て値を調整しない
- **関門で使う値と規則の完全な組（§7.2）は、②a で、関門を走らせる前に、理由とともに宣言して固定する**。②b はその組を変えずに一度だけ走らせる。③はその組を引き継いで変えない
- 組を変える必要が出たら、そこで止め、理由を書いて技術審査を経る。関門の結果を見て、値や規則を探し直さない
- この文書（①）が決めるのは、固定する責務と方法と、試験の原則までである。値そのものは②a で決める

### 7.2 固定する組（②a で、関門の最初の実行の前に）

| 区分 | 固定するもの |
|---|---|
| 予定と窓 | 手がかりの予定の全体（数と間隔）、o、W。命題 T-4 の条件を満たすこと |

- 源は入口に刺激を受けないので、窓の中の源の発火は、内在の駆動と、ほかの Unit を経た駆動（1 回あたり高々 w_max）から生じる（N-3・N-4 §2.4.6）

### 7.4 合成の seed の部分（②b で、一度だけ）

- ②a で固定した組で一度だけ走らせ、**次の実行可能性の量だけ**を出す

次の段階（AI に二つの行動のどちらかを選ばせる）で使う AS2b の、作り方の約束事です。
