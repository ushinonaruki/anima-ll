# 実験設計の常設チェック（v0.3）

> 作成：2026-10-11（Claude）。v0.3：ChatGPT 再レビュー反映。A3 を「適用対象を結果と独立に先に決める → 対象の中の 0 の寄与はふつうに 0 → 対象そのものがなければ N/A」に直した（v0.2 は「空の和は 0」と「該当なしは N/A」が衝突していた）。v0.2：ChatGPT レビュー（#64）反映。A6（数式の形そのものの恣意性）を追加／A3 で「0 の項」と「該当なし」を区別／C3 の確認を、解析・合成の契約テスト・独立した既存の測定だけに限定した。v0.1：0012〜0014 で実際に起きた失敗・修正から、事前登録を書く前と道具を書く前に毎回確かめる項目を集めたもの。各項目の出どころの実験を書く。項目は、新しい実験で同じ種類の問題が起きたときに足す
> 使い方：事前登録の案（README・protocol.yaml）の PR に、このチェックを通したことを書く。満たさない項目があれば、その理由を README に書く

## A. 判定の量を決める前

| # | 確かめること | 出どころ |
|---|---|---|
| A1 | **判定の量の符号が、保存則・単調性・介入の定義だけで解析的に決まっていないか**。決まっているなら、その量の「＞ 0」は向きの検定ではなく効果の有無の検定である。そう名づけて登録するか、向きが経験的に決まる量に替える | 0014 §9.3（sign(W_probe) × ΔR は、単調な Unit の力学と介入の定義から負になれなかった） |
| A2 | 向きを揃える量が、同じ判定の結果から決まっていないか（自己参照）。向きは、判定の窓・判定の量より前に決まるもので揃える | 0013 v0.2（H_A の向きを、後の窓が作った重みではなく出生時の側 b_ij で揃えた） |
| A3 | **式を適用する対象を、結果と独立に先に決める**。(1) どの対象（個体・組・試し）にその式を適用するかを、判定の結果を見る前に決まる条件で事前登録する。(2) 適用対象が存在するなら、その中の寄与 0 の項（例：b ＝ 0 の組）は、専用の if 分岐を置かずふつうの算術で 0 として扱う。(3) **適用対象そのものが存在しない**（例：適格な組が 1 つもない個体、始めの差が 0 で持続を問えない個体）なら N/A とし、0 に潰さない。N/A を判定の分母に入れるかは事前登録で明記する。組み合わせごとの結論の表のような、人工の分岐を作っていないか | 0013 v0.4（b ＝ 0 は 0 の項、適格な組のない個体は分母の外）、0014 v0.2（p×w の表を置かない） |
| A4 | 読み出しが、調べたい成分（例：接続の状態）と別の成分（例：Unit の興奮しやすさ）を混ぜていないか。混ざるなら、同じ時点の複製の対で、調べたい成分だけを変える介入にする | 0012 の事後の解析 → 0014 の設計 |
| A5 | 介入が、名前どおりのものだけを変えているか（名前は変えたものに合わせる。例：「接続の状態を揃える」ではなく「weight 成分の B/C 方向の非対称だけを消す」） | 0014 v0.1 |
| A6 | **数式の形そのものが恣意的でないか**。比・平均・絶対値・符号・正規化・切り詰め・閾値などの関数の形について、(1) なぜこの形なのか、(2) 問い・対称性・保存則・既存の力学から導けるか、を README に書く。同じくらいもっともらしい別の式があるなら、主の判定として 1 つに潰さず、構成量を別々に出す（記録に回す）。比は、分母が 0 になりうること・正規化の選び方が新しい自由度になることを特に確かめる | ChatGPT の Q4 の検討（「weight の寄与 ÷ Unit の寄与」の比は、新しい関数形・正規化・0 除算を持ち込む） |

## B. 時刻と runtime の順序

| # | 確かめること | 出どころ |
|---|---|---|
| B1 | 介入を入れる時点・読み出しの時点が、runtime の 1 Pulse の処理の順序（重みの固定 → 伝達の凍結 → 次の Pulse に届く → 終わりに可塑性）と対応しているか。比べる 2 腕が、介入より前に分かれていないか | 0014 v0.3（t0 − 1 の終わりで分けると、A の発火の前から 2 腕が分かれうる） |
| B2 | 「何かを反映した状態」を測る時刻が、その出来事の応答と可塑性の更新が終わった後か（感覚の出来事の Pulse と、Unit の応答の Pulse は違う） | 0014 v0.3（W_post を最後の C の 11971 ではなく 12000 で測る） |
| B3 | runtime の順序から導いた主張は、契約テストで実物の runtime を通して確かめる | 0012（T_min ＝ 9 の契約テスト）、0014（2 腕の t0 ＋ 1 の一致、A が発火しないときの ΔR ＝ 0） |

## C. 値

| # | 確かめること | 出どころ |
|---|---|---|
| C1 | 新しい数値は、既にある値（力学の時定数、試行の間隔など）から導けないか。導けない値は README の表に「新しく選んだ値」として理由を書く | 0014 v0.2（試しの間隔・数を τ_a から） |
| C2 | 単位をそろえているか（秒と Pulse など） | 0014 v0.3（adaptation_tau ÷ pulse_interval_seconds） |

| C4 | 乱数の流れは、数値の式ではなく名前で分ける | 0014 v0.3（"0014-shuffle:<seed>"） |

| # | 確かめること | 出どころ |
