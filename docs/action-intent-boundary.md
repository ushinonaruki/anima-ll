# 行動の意図（ActionIntent）の境界と契約 v0.1（案）

> 作成：2026-10-08（v0.1.1：AI1 で生成の単位・方式を固定しない、AI3 の記録は運用のログで Unit には返さないと明記）。Status：**境界と契約だけの案。実装はしない。行動を選ぶ規則・学習・価値は定義しない**
> 前提：恣意性監査 §3.6・3.7 で採用した方向の 2「行動するかどうかは Neuroarchitecture が決める（Kernel・Effector は選ばない）」、内部表現の原則（`docs/internal-representation-principles.md`）の R6 と §6 の 2
> 似た文書：計算資源境界 仕様（`docs/compute-boundary-spec.md`）。ComputeIntent が「内部で高価な計算をしたい」という意図なのに対し、ActionIntent は「外界に作用したい」という意図

---

## 1. なぜ実装より先に境界を決めるか

行動を選ぶ仕組みを作る前に、行動の意図が **どこから生まれ、誰が何をし、結果がどう戻るか** だけを決めておく。そうすれば、内部表現や可塑性を考えるときに「この内部の状態は、外界との閉じたループにどうつながるのか」を見失わない。一方で、「なぜ X を選ぶのか」「どう学習して X を選ぶのか」「X と Y のどちらがよいか」は、ここでは決めない（内部表現の原則 §6 の 6・7）。

## 2. 因果の流れ

```text
【Neuroarchitecture】
  内部の状態（活動・接続・時間的な状態）
    ↓
  ActionIntent が生まれる（認知の出来事）
──────────────────────────────
【Runtime】
    ↓ 受け取り、記録し、Effector に渡す（選ばない・消さない）
【Effector（Environment）】
    ↓ 外界に作用する（選ばない）
【外界（Environment の規則）】
    ↓ 外界の状態が変わる
【Receptor（Environment）】
    ↓ 変わった外界を感覚として受け取る
【Neuroarchitecture】
  次の Pulse 以降の内部の状態が変わる
```

## 3. 契約

| 番号 | 契約 |
|---|---|
| **AI1** | ActionIntent は **Neuroarchitecture からだけ** 生まれる。Neuroarchitecture の中の認知の出来事として成立する。**具体的にどの単位が・どの方式で生むかは未決定**（1 つの Unit の出力部品かもしれないし、複数の Unit の状態の競合や統合の結果として成立するのかもしれない）。Runtime・Kernel・Effector・Environment は ActionIntent を作らない |
| **AI2** | **Kernel は ActionIntent を選ばない**。出すか出さないか、どれを出すかを判断しない。言語化などで呼ばれても、行動を取りやめる（拒否する）ことはしない（今の `utter` の「口に出さないなら何も出力しない」はこの契約に反する足場。恣意性監査 §3.6・3.7 の D） |
| **AI3** | **Effector は ActionIntent を選ばない**。受け取った意図を実行するだけ。実行できなかったときは、その事実を **Runtime・Effector の運用のログ** に記録する（判断して取りやめるのではない）。ただし、**Unit に「失敗した」という認知の信号を直接返さない**（AI6）。本人が失敗に気づくなら、「外界・身体が変わらない／予想と違う」ことを Receptor から受け取って内部で気づくか、将来検討する遠心性コピー（§5 の 1）を通じてである |
| **AI4** | **Runtime は ActionIntent を選ばない・黙って消さない**（計算資源境界と同じ）。生まれた意図は記録し、Effector に渡す。同じ Effector への意図が同じ Pulse に重なったときの扱いは未決定（§5 の 2）。決めるときも、Runtime が意味で選ぶ規則にはしない |
| **AI5** | **ActionIntent は「外界に作用したい」という意図であって、成功した結果ではない**。意図が生まれたことと、外界がどう変わったかは別の出来事として扱う |
| **AI6** | **行動の結果は、外界から Receptor を通ってだけ戻る**。Effector や Environment が「成功した」「よかった」という信号を Unit に直接返さない（返すと、価値や正解が外から持ち込まれる） |
| **AI7** | **行動の種類（どんな行動がありうるか）は Environment が持ち、脳の設計図には ID だけを宣言する**（今の Effector の ID と同じ）。行動の ID に意味の名前を付けない（人工世界では X・Y など）。設計図の側で「X ＝ 食べる」のように意味づけしない |
| **AI8** | **行動の価値・選択の規則は、この文書では定義しない**。「ある内部の状態なら X を出す」という規則を、症状に合わせて書かない（恣意性監査 §2.2 の 4 つの問い） |
| **AI9** | **「何もしない」は ActionIntent がないこととする**。何もしないことを意図として選ぶ仕組みは作らない。ただし「休む」のように外界（身体）に作用する行動は、Environment が行動の種類として定義してよい（AI7） |
| **AI10** | **話す（発話）も ActionIntent の一つ**。「話すか」＝ Neuroarchitecture（ActionIntent が生まれるか）、「どう表現するか」＝ 言語の Kernel（内容を自然な日本語にする。AI2 により取りやめない）、「実際に出す」＝ Effector（恣意性監査 §3.6・3.7 の採用した方向の 2） |

## 4. ComputeIntent との違い

| | ComputeIntent | ActionIntent |
|---|---|---|
| 何の意図か | 内部で高価な計算をしたい | 外界に作用したい |
| 渡す先 | Kernel（計算器） | Effector（外界への作用） |
| 結果の戻り方 | KernelResult として、意図を出した Unit に返る | **外界の変化として、Receptor から戻る**（AI6）。意図を出した Unit に直接は返らない |
| 選ばない層 | Runtime・Kernel | Runtime・Kernel・Effector |

発話のように、ActionIntent の実行の途中で言語の Kernel を使う場合も、Kernel は表現を作る計算器として呼ばれるだけで、行動を選ばない（AI2・AI10）。

## 5. 未決定の問い（この文書では決めない）

1. **遠心性コピー（efference copy）**：「自分が X を出した」という事実を、外界の結果とは別に内部で知れるようにするか。生物では運動の指令の写しが内部に送られ、感覚の予測に使われる。可塑性（予測誤差）を設計するときに一緒に決める
2. **同じ Effector への意図が重なったとき**：同じ Pulse に、同じ Effector へ複数の意図が届いたときの扱い。行動の選択そのものに関わるので、Runtime の工学の規則で意味的に選ぶことはしない。Neuroarchitecture の側で起きないようにするのか、Effector の物理的な性質（同時にはできない）として扱うのか、を決める
3. **行動の強さ・持続**：意図が「出す／出さない」だけか、強さや長さを持つか
4. **今の発話（u3 ＋ `utter` テンプレート）の置き換え**：今は Kernel が「話すか」を決めている（AI2 違反の足場）。実際に置き換えるのは、内部表現の原則 §6 の 6（閉じたループへつなぐ）のとき

## 6. 実装するときに確かめること（契約テストの候補）

- ActionIntent が Neuroarchitecture 以外から生まれないこと（AI1）
- 実行できなかったことが運用のログには残り、Unit には認知の信号として直接届かないこと（AI3・AI6）
- Kernel・Effector・Runtime が、受け取った意図を取りやめたり別の意図に替えたりしないこと（AI2〜AI4）
- 結果が Receptor 以外の経路で Unit に届かないこと（AI6）
- 行動の ID が脳の設計図で意味の名前を持たないこと（AI7）
