# 内部表現の原則 v0.1（案）

> 作成：2026-10-08。Status：**原則の案。方式・データ形式・次元数・アルゴリズムはまだ決めない。実装もしない**
> 前提：恣意性監査（`docs/arbitrariness-audit.md`）§3.1〜3.9 の完了と、§3.6・3.7 で採用した二つの方向
> 1. AnIma-ll の内部の思考を、LLM どうしの自然言語の会話として定義しない
> 2. 行動するかどうかは Neuroarchitecture が決める（Kernel・Effector は選ばない）
>
> この文書が答える問い：**AnIma-ll の中で、ある経験・対象・状態の「意味」は、何に宿ってよく、何に宿らせてはいけないか**

---

## 1. なぜ方式より先に原則を決めるか

最小の核の監査で、これまで育ててきたのは **意味の中身ではなく、認知の時間の構造と活動の構造**（いつ発火するか、自発活動、順応による落ち着き、履歴による感受性の変化）だと分かった（台帳 §6）。画面で見えていた「考えているらしさ」は、ほぼ LLM とテンプレートの産物だった（§3.6・3.7）。

ここで「128 次元のベクトルにする」のような形式から決めると、形式の選び方そのものが新しい足場になり、L2-2 や IO テンプレートと同じく、気づかないうちに意味を持ち込む。先に「意味が宿ってよい場所／いけない場所」を決め、方式はそれを満たすものの中から、事前登録した実験で選ぶ。

## 2. 意味が宿ってよいもの

| 宿ってよいもの | 説明 |
|---|---|
| **多数の Unit の活動のパターン** | 1 つの Unit ではなく、複数の Unit の活動の組み合わせとその時間の変化（分散した表現） |
| **Unit 間の接続と、その重みの変化** | 経験（可塑性）によって変わった接続。Life History が脳の構造に残る場所 |
| **時間的な状態** | activity・順応のような、時間とともに変わる内部の状態 |
| **過去の活動の再活性化** | 以前と似た活動のパターンが再び生じること（想起・Replay の土台） |

意味は、これらの **組み合わせとして分散して** 存在してよい。どれか一つの場所に完成した形で置かれる必要はない。

## 3. 意味を宿らせてはいけないもの

| 宿らせてはいけないもの | 理由 |
|---|---|
| **Unit の名前・ID・番号** | 凍結 5 点の 1。名前に意味を持たせると、役割を人間が与えることになる |
| **プロンプトやテンプレートの文章** | §3.6・3.7。文章の指示は人間が与えた役割であり、AnIma-ll 本人の認知ではない |
| **LLM の事前知識・LLM の出力の文章そのもの** | Kernel は交換可能な計算器。Kernel を替えたら本人が替わる、という作りにしない |
| **LLM の埋め込みベクトル（embedding）をそのまま内部表現にすること** | 文章 → 埋め込み → 内部表現、では prompt leakage が **embedding leakage** に替わっただけになる |
| **1 つの payload に完成した意味を入れること** | 1 つの Delta の中身が「意味そのもの」だと、分散した表現・経験による変形が起きる場所がなくなる |
| **記憶のデータベースの文章だけで人格を作ること** | 永続化は工学の層で支えてよいが、文章の記録そのものを本人の記憶・人格にしない |
| **環境が付けたラベル（「赤」「食べ物」「嬉しい」など）** | 外界の名前は、AnIma-ll が経験から作る表現ではない |

## 4. 外界との境界での外部モデル（感覚器としての使い方）

外部のモデル（画像・音声・言語のエンコーダや LLM）は、**感覚器** にはなってよい。

```text
カメラ・音声・文章
   ↓
外部のエンコーダ・Kernel（交換可能）
   ↓
一時的な感覚の特徴（sensory features）
   ↓
AnIma-ll の中で、経験に依存して形成される表現       ← ここが本人
```

- 外部モデルの出力は「その瞬間の感覚の特徴」として受け取る。**「このベクトルそのものが AnIma-ll の思考」とはしない**
- 内部の表現は、その特徴を材料に、AnIma-ll の経験（活動・接続の変化・再活性化）によって形成される
- 同じように、外へ出すときの言語化（「どういう日本語にするか」）は言語の Kernel が担ってよい（§3.6・3.7 で採用した方向の 2）

## 5. 内部表現の契約（方式によらず満たすこと）

| 番号 | 契約 |
|---|---|
| **R1** | 意味を 1 つの payload に完成した形で入れない |
| **R2** | Unit 群の状態として分散して表せる |
| **R3** | 経験によって変形できる（同じ入力でも、履歴によって内部の活動が変わりうる） |
| **R4** | Kernel（LLM・外部エンコーダ）を交換しても、内部の状態そのものは残る |
| **R5** | Unit の力学は意味を「読まない」。表現は活動と接続の中にあり、Unit が中身を解釈して分岐する if 文を作らない（台帳 §3.10 の原則を引き継ぐ） |
| **R6** | 行動の意図（ActionIntent）は内部の状態から出る。外へ作用する出口があり、その結果が次の内部の状態を変える（閉じたループ） |

## 6. 進める順番（案）

1. **この原則を決める**（この文書）
2. **最小の行動の意図（ActionIntent）の出口を作る**。賢い行動選択はまだ作らない。内部表現を受け身の世界だけで設計すると、何を表すべきかが宙に浮くため
3. **可塑性**（記憶より先）。「同時に活動した」「時間的に近かった」「結果が返った」などで接続が変わる原理。**何を学習の信号にするかは独立に監査する**（下の未決定の 1）
4. **記憶は、可塑性と再活性化から設計する**。最初から「表に文章を保存」ではなく、短い痕跡 → 再活性化 → 接続の変化 → 一部の長期化、の順。永続化は工学の層で支える
5. そのあと、似た経験の結びつき、睡眠中の Replay（L3）へ

## 7. 最初の実験の場（案）：LLM も自然言語も使わない小さな人工世界

```text
意味のない数種類の刺激（A・B・C のパターン）
   ↓ Receptor（Environment）
Unit のネットワーク
   ↓
2〜3 種類の行動の意図（X・Y・何もしない）
   ↓ Effector（Environment）
環境から結果が返る（次の刺激が変わる）
   ↓
可塑性
```

- 刺激にも行動にも意味の名前を付けない（「赤」「食べ物」「嬉しい」としない）
- 見る問い：**同じ刺激でも、過去の経験によって、内部の活動や次の行動の意図が変わるか**
- LLM を使わないので、うまくいったときに「LLM が賢かったから」という逃げ道がない
- 今のアーキテクチャ（Ports & Adapters、Environment の分離）に合う。人工世界は **Environment の実装**（Receptor・Effector・その間の規則）として作り、脳の設計図とは分ける

## 8. 未決定の問い（この文書では決めない）

1. **可塑性の学習の信号は何か**：「結果が返った」を使うと、どの結果が「よい」かという価値が要る。価値を人間が手で書くと、L2-2 と同じ種類の持ち込みになる。AnIma-ll の中心の一つである **感情（価値・快不快）** を、ここで独立した原理として設計する必要があるかもしれない
2. **ネットワークの大きさと接続の作り方**：分散した表現には、今の 4 Unit では足りない。手で配線を描かない（§3.8）とすると、接続を作る規則（決まった規則・乱数・経験からの形成）を決める必要がある
3. **今の Unit の力学（`SimpleActivityDynamics`）を土台に使い続けるか**：スカラーの activity・hard reset・決定論的な発火（§3.9）のままで、分散した表現が作れるか
4. **人工世界の設計そのものの恣意性**：「正しい振る舞い」が出るように世界を設計すると、症状合わせと同じことになる。世界の規則も事前登録し、台帳で監査する
