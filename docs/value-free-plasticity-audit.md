# 価値を使わない可塑性の設計監査 v0.2（案）

> 作成：2026-10-10（v0.2：ChatGPT レビュー反映。重みは受け手の Unit ではなく接続そのものの状態として個体の Neuroarchitecture に置く案に、P1・P2 は「発火の時刻はあるが、接続ごとに読める一般的な発火の出来事がまだない」に、P5 は「順応は新奇さの検出器ではない」に直した）。Status：**設計の監査の案。方式・式・値はまだ決めない。実装もしない**
> 前提：内部表現の原則（`docs/internal-representation-principles.md`）§6 の 3「価値を使わない可塑性」、§8 の 1（表現を形づくる可塑性は価値がなくてもありうる）。ActionIntent の境界（`docs/action-intent-boundary.md`）
> この文書が答える問い：**価値（よい・わるい）を使わずに、経験で接続が変わる原理として、何がありうるか。それぞれは何をモデル化し、今の Unit の力学で表せ、外から意味や正解を持ち込まないか**

---

## 1. 候補を並べる

| 記号 | 候補 | 一言でいうと |
|---|---|---|
| **P1** | 相関（共起） | 一緒に活動したもの同士のつながりが変わる |
| **P2** | 時間の順序 | A の少し後に B が活動すると、A → B のつながりが変わる |
| **P3** | 再活性化 | 入力がないときに、以前の活動のパターンが再び起き、そのあいだにつながりが変わる |
| **P4** | 予測誤差 | 予測と実際が違ったときに、つながりが変わる |
| **P5** | 新奇さ | 慣れていない活動のときほど、つながりが変わりやすい |

## 2. それぞれの監査

### P1 相関（共起）

| 観点 | 監査 |
|---|---|
| 何をモデル化するか | 同時に起きたことの結びつき（連合）。生物ではヘッブ型の可塑性 |
| 今の力学で表せるか | **力学の内部には、送り手・受け手それぞれの発火の時刻（Pulse）の情報がある**。ただし今の実装では、「送り手が発火した」ことと「Delta が届いた」ことは同じではない（relay・kernel_request の Delta は、出力の部品の意味や Kernel の結果に依存する）。**接続ごとの局所的な可塑性が読むための、一般的な発火（活動）の出来事の表し方がまだない**（§3 の 2）。重みが変わる接続の状態も要る（§3 の 1） |
| 意味・正解を持ち込まないか | **持ち込まない**。読むのは「いつ発火したか」だけで、中身も価値も読まない（R5） |
| 気をつけること | 重みが増え続けて暴走しやすい。上限・正規化・ゆっくり戻る、などの仕組みがいる。その値は新しい仮置きになるので、台帳で比（w／θ など）として記録する。「同時」の幅（同じ Pulse か、前後何 Pulse か）も決める必要がある |

### P2 時間の順序

| 観点 | 監査 |
|---|---|
| 何をモデル化するか | 「A の後に B が来る」という時間的な関係（予測の土台）。生物では STDP（発火の時刻の差で強まる・弱まるが決まる）に近い |
| 今の力学で表せるか | **原理は合う**。Pulse の境界があるので、「送り手の発火 → 次の Pulse に受け手に届く → 受け手の発火」という向きが自然に決まっている。ただし P1 と同じく、接続ごとに読める一般的な発火の出来事と、変わる接続の状態が要る（§3 の 1・2）。少し離れた順序を扱うには、送り手の最近の活動を少しのあいだ覚えておく **発火の痕跡（activity trace）** がいる（「eligibility trace」という名前は、後から来る第三の信号を待つ学習則でよく使われ、価値の含意が出るので、今は使わない）。痕跡の時定数は新しい値になる（秒で書く。台帳 §3.9） |
| 意味・正解を持ち込まないか | **持ち込まない**。読むのは発火の時刻の前後だけ |
| 気をつけること | 今の時間の解像度は 1 Pulse ≒ 1 秒と粗い。生物の STDP（数十 ms）とは時間の尺度が違うので、「STDP を再現した」とは言わない。また生物の可塑性は発火の時刻だけで決まる一つの法則ではなく、発火の頻度・脱分極・協調性・神経修飾などにも依存する。「STDP に近い」に留める。A と B の間隔が、痕跡の時定数・入力を積み上げる時間の窓（τ_m ≒ 6.2 秒）・保持期間とどういう比になるかで結果が変わる。**P1 は、時間の差が 0 の場合の P2 として、まとめて扱える可能性がある** |

### P3 再活性化

| 観点 | 監査 |
|---|---|
| 何をモデル化するか | 経験したあとに、同じ活動のパターンがもう一度起き、そのあいだに結びつきが固まる（定着・Replay） |
| 今の力学で表せるか | **土台はある**。入力がなくても活動が止まらない（内在的駆動）。ただし今の自発活動は、経験とは関係のない決まった周期で、「以前のパターンの再現」ではない |
| 意味・正解を持ち込まないか | 持ち込まない（何を再活性化するかを人間が選ばなければ） |
| 気をつけること | **P3 は独立した学習の規則というより、「いつ」可塑性を働かせるかの状況** である。再活性化のあいだに働く規則は、P1・P2 そのもの。したがって P1・P2 の後に、記憶・Replay（内部表現の原則 §6 の 5、L3）と一緒に設計する |

### P4 予測誤差

| 観点 | 監査 |
|---|---|
| 何をモデル化するか | 予測が外れたときに学ぶ。表現そのものが予測によって形づくられる、という考え方（予測による学習） |
| 今の力学で表せるか | **今のままでは難しい**。「何が予測で、何が実際か」を区別する必要がある。たとえば、ある Unit に「内側からの予測の入力」と「外からの感覚の入力」が別々に届き、その差を見る、という構造が要る。今の Unit は入力を区別せず、刺激をひとつの数（重みの合計）にまとめてしまう |
| 意味・正解を持ち込まないか | 局所的に（Unit ごとに）差を見るなら持ち込まない。**ただし、誤差をネットワーク全体に一つの数として配る形にすると、価値の信号（報酬）と見分けがつかなくなりやすい** |
| 気をつけること | 入力の種類を分ける Unit の構造の変更が要る。どの Unit が何を予測するかを人間が配線で描くと、§3.8 と同じ「配線による役割の付与」になる。P1・P2 で「A の後に B 側が活動しやすくなる」が起きれば、それ自体が予測の芽になるので、P4 はその後に設計する |

### P5 新奇さ

| 観点 | 監査 |
|---|---|
| 何をモデル化するか | 慣れていないことほど、よく学ぶ（学習の強さの調整） |
| 今の力学で表せるか | **まだ表せない**。今の順応（L2-1）が覚えているのは「この刺激を何度も見た」ではなく、「この Unit が最近よく発火した」だけである。同じ Unit に A と B が届くなら、A を繰り返して順応が高まったところに初めて B が来ても、B への反応まで抑えられうる。**今の順応は、活動の履歴に依存する反応の大きさの調整（gain の調整）であって、新奇さの検出器ではない** |
| 意味・正解を持ち込まないか | 持ち込まない（何が新しいかを人間がラベルで決めなければ） |
| 気をつけること | **P5 は単独の学習の規則ではなく、ほかの規則（P1・P2）の強さを調整するもの**。刺激に特有の内部の表現が経験で形づくられたあとに、その結果として新奇さに似た調整が生じるかを、後で確かめる。ここで「好奇心」「探索」と呼ばない（内部表現の原則 §9） |

## 3. どの候補にも共通する設計の問い

1. **変わる重みは、どこにあるのか（層の問題）**：今の結合の重みは脳の設計図（Manifest）に書かれ、**Runtime**（`ProjectionRouter`・`DeltaCanonicalizer`）が Delta に付けて配っている。可塑性は認知の仕組みなので、Runtime が重みを持ったり書き換えたりすると、計算資源境界と同じ種類の層の混同になる。**重みを Runtime から出すことには賛成**。ただし、受け手の Unit の状態にもしない。重みは Unit の属性ではなく、**送り手 → 受け手という接続そのものの状態** だからである（受け手の Unit に押し込むと、複数の入力の辺や、将来の接続の生成・消滅を Unit の状態に抱え込ませる別の結合になる）。候補は次の分け方：

   ```text
   Manifest（脳の設計図）
   ├─ 初期の配線（topology）
   ├─ 初期の重み
   └─ 可塑性の規則
   個体の Neuroarchitecture の状態（Life History で変わる）
   └─ 接続の状態（ConnectionState／ProjectionState）
         └─ 今の重み
   Runtime
   └─ 届けるだけ（可塑性を決めない・重みを書き換えない）
   ```

   - 経験で変わった重みは個体の側に残る。今の個体のスナップショットは Unit の状態だけを保存しているので、接続の状態も保存の対象に足す必要がある
   - 将来、接続の生成・消滅（構造的な可塑性。vault「経験依存の Unit 構造変化（仮案）」）へ進むときも、接続の状態として扱える
   - Runtime が配るときに今の重みを読み取りだけで使うのか、受け手が接続の ID から参照するのかは、次の境界の仕様で決める
2. **発火を、中身のない信号として伝える出力が要る**：今の Unit の出力は、relay（新しく届いた中身を転送）と kernel_request（LLM の結果を出す）だけで、**「発火した」こと自体を伝える出力がない**。LLM を使わない人工世界で可塑性を確かめるには、発火したら中身のない Delta を出す出力の部品が要る
3. **規則が読んでよいもの**：受け手の Unit が局所的に知れることだけ（送り手からいつ Delta が届いたか、自分がいつ発火したか、自分の activity・順応、痕跡）。Runtime の状態（列・待ち時間・Kernel の速さ）や、Delta の中身、環境のラベルは読まない
4. **安定性**：重みの暴走を防ぐ、何らかの安定化の仕組みが必要になる可能性が高い。方式（上限・正規化・ゆっくり戻る など）は未決定。その仕組みと値も監査の対象で、振幅は比（w／θ）で書く（台帳 §3.9）
5. **確かめる場**：受け身の人工世界（内部表現の原則 §6 の 4）。今の 4 Unit の配線ではなく、A・B・C を受け取る感覚の Unit と、そのあいだのつながりが要る。その配線も足場として事前登録し、台帳で監査する（手で描くなら、なぜその形かを書く。規則で作るなら、規則を書く）

## 4. 監査の結論（案）

| 候補 | 位置づけ（案） |
|---|---|
| P1 相関 | **最初の候補**（P2 の時間差 0 の場合として、P2 とまとめられるかを検討） |
| P2 時間の順序 | **最初の候補**。受け身の人工世界の「A の後に B」を確かめる問いと直接対応する |
| P3 再活性化 | 規則ではなく「いつ働かせるか」の状況。記憶・Replay と一緒に、P1・P2 の後で |
| P4 予測誤差 | P1・P2 の後。入力の種類を分ける Unit の構造の変更が要る。全体に配る誤差の信号は価値と混ざりやすいので避ける |
| P5 新奇さ | 単独の規則ではなく、学習の強さの調整。今の順応は新奇さの検出器ではない。刺激に特有の表現ができたあとで検討する |

最初に入れる候補は **P1・P2（時間の窓つきの共起）**。ただしこれは「よさそうだから」選ぶのではなく、次の理由による。

- 原理として、Pulse の境界と発火の時刻という、今の力学にある情報だけで局所的に表せる
- 価値も意味も読まない
- 最初の確かめる問い（同じ刺激でも、経験によって内部の活動が変わるか）に、**新しい意味や価値の仕組みなしで** 答えられる

ただし、**最小の構造の変更は必要** である：変わる接続の状態（§3 の 1）と、接続ごとに読める一般的な発火（活動）の出来事（§3 の 2）

## 5. 決めたいこと（この文書では決めない）

1. P1 と P2 を一つの規則（時間の窓つきの共起）として扱うか、別々にするか
2. 接続の状態（ConnectionState）を個体の Neuroarchitecture に置く形にするか（§3 の 1）。Runtime と Neuroarchitecture の境界の変更になるので、計算資源境界と同じく仕様として先に書く
3. 一般的な発火（活動）の出来事を、どう表して接続に伝えるか（§3 の 2）。出力の部品として足すのか、Runtime の配送の仕組みとして表すのか
4. 受け身の人工世界の設計（刺激の種類と出方、感覚の Unit とつながりの作り方）。事前登録の対象
